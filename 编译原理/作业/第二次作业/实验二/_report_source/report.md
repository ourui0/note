## 1　实现功能与选做范围

在实验一的 Flex/Bison 词法与语法分析器基础上，使用 C99 手写语义分析模块，对语法树进行类型检查，覆盖实验手册规定的错误类型 1—17：未定义与重复定义、赋值及左值检查、运算与返回类型检查、函数实参匹配、数组访问、结构体及其成员检查。

实验二仅实现选做 2.3：结构体采用结构等价。结构体名称与字段名称不参与类型比较，字段数量、声明顺序及对应字段类型必须一致；嵌套结构体递归比较。数组不展开，只比较维数与元素类型，忽略各维长度。例如，字段依次为 int、float 的两个不同名结构体可以相互赋值；交换字段类型顺序后则不等价。

未实现选做 2.1、2.2：函数声明报告 B 类语法错误；所有变量和形参共用全局命名空间，不同函数中重复的变量名仍报告错误 3。词法层保留实验一的注释支持。

## 2　核心实现

语法树与语义分析分离。parser.y 构造带源码行号的语法树，semantic.c 完成检查。只有词法、语法分析均成功时才调用 semantic_analyze；合法程序保持静默，出错时向 stdout 输出错误类型、行号和说明。完成源文件分析后统一返回 0。

符号与类型统一建模。链地址哈希表区分变量、函数和结构体标签；字段只保存在所属结构体的有序字段链中，因此字段查找和重名检测不会污染变量表。类型结点表示基本类型、数组、结构体、函数及错误占位类型。按源码顺序登记定义，函数在分析函数体前登记，以支持递归调用。

类型等价集中实现。赋值、初始化、返回值与参数匹配共享同一递归比较函数，避免各处规则不一致。数组按嵌套层次比较；结构体按字段类型序列比较，并记录比较中的类型对。结构等价不改变成员访问规则：访问 a.x 时仍按 a 自身的结构体定义查找 x。

抑制级联错误。表达式分析同时返回类型和左值属性。未定义变量等根本错误产生错误占位类型，父表达式不再追加由其直接引起的类型不匹配；其他语句继续检查。诊断按行号整理，同一行保留首先发现的错误。语法树与语义对象分别使用分配链，在程序结束前集中释放。

## 3　编译与运行

提交包解压后顶层为 Code/ 和 report.pdf。Code/ 中包含 parser.h、lexer.l、parser.y、parser.c、semantic.h 和 semantic.c 六个源文件。依赖为支持 C99 的 GCC、Flex 和 Bison；与课程指定的 GCC 7.5、Flex 2.6.4、Bison 3.5.1 接口兼容，不使用第三方 C 库。

推荐逐条编译。在解压目录执行以下命令；最后一条命令中的 input.cmm 替换为实际源文件路径（该路径相对于 Code 目录）：

```text
cd Code
flex -o lex.yy.c lexer.l
bison -d -o syntax.tab.c parser.y
gcc -std=c99 -Wall -Wextra parser.c semantic.c \
    syntax.tab.c -o parser
./parser input.cmm
```

parser.y 已包含生成的 lex.yy.c，因此不要将 lex.yy.c 再单独编译或链接。词法器启用 noyywrap，程序自己提供 main 和 yyerror，以上命令无需链接 libfl 或 liby。继承的语法错误恢复规则可能产生 Bison 冲突警告；本次检查中不影响代码生成及样例运行。

也可使用课程 Makefile_ref。在安装了 Flex/Yacc 运行库的课程 Linux 环境中，把 Makefile_ref 复制为 Code/Makefile，再执行 cd Code、make 和 ./parser input.cmm。该 Makefile 自动发现 semantic.c，并使用 -lfl -ly 链接；macOS 若缺少这两个运行库，使用上面的逐条编译命令。

输出示例为 Error type 5 at Line 4: Type mismatched for assignment.。正确输入不打印语法树或其他内容。词法、语法错误分别使用 A、B 类诊断；语义错误使用数字编号。命令行参数不正确或输入文件无法打开属于运行条件错误，输出提示并返回 2。
