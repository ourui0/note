单⽂件组件（SFC）：为什么这样设计？
传统三⽂件 vs SFC
维度 传统三⽂件（HTM L  / CSS / JS） SFC（.vue）
⽂件组织 按技术分层 按组件聚合
复⽤单元 零散，跨⽂件复制 组件整体复⽤，⾃包含
样式隔离 全局 CSS 互相污染 scoped  只作⽤本组件
维护成本 改⼀功能需跨多⽂件 改动集中在⼀个⽂件
组件是前端⼯程化的基本单元
SFC 让每个组件⾃包含，⼤型应⽤可拆分为数百个独⽴组件按需复⽤。

Node.js — JavaScript 的后端⼒量
Node.js = V8 引擎 + 事件循环 + ⾮阻塞 I/O
传统服务器（多线程模型）：
  请求 1 ──► 线程 1 [ 等待数据库 ] ──────────► 响应 1
  请求 2 ──► 线程 2 [ 等待⽂件 IO] ──────────► 响应 2
  请求 3 ──► 线程 3 [ 等待 ...]    ──────────► 响应 3
  （线程池耗尽  → 新请求排队等待）
Node.js （事件驱动  + ⾮阻塞）：
  请求 1 ──► 发起 IO → [ 继续处理其他请求 ]
  请求 2 ──► 发起 IO → [ 继续处理其他请求 ]
  请求 3 ──► 发起 IO → [ 继续处理其他请求 ]
  IO 完成  ──► 回调函数处理结果  ──► 响应
  （单线程  + 事件队列，⾼并发不阻塞）
核⼼优势：
特性 说明
⾼并发 事件驱动，单线程处理⼤量并发连接
前后同语⾔全栈均⽤ JavaScript，降低切换成本
⽣态丰富 npm 拥有 200 万+ 包 30

Express 服务端（server.js）：

const cors    = require('cors');

 思考题：路由的两种形态
前端路由（Vue Router）vs 后端路由（Express）
前端路由（ SPA 模式）：
  ⽤户点击  " 关于我们 "
  → URL 变为  /about
  → Vue Router 拦截，加载  About.vue 组件
  → ⻚⾯不刷新，只替换组件
  → 服务器实际上没有  /about 这个⽂件
后端路由（传统模式）：
  ⽤户点击  " 关于我们 "
  → 浏览器向服务器请求  /about
  → 服务器查找路由表，返回对应  HTML ⻚⾯
  → 整⻚刷新

① W eb 前端 = 三层分⼯

服务和实时场景。
⼀条技术演进线索：
静态 HTM L  → 动态 JS → AJAX 异步 → 前端框架 → 组件化 → 全栈 JS
