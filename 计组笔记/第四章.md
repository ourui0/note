# 第四章 指令系统详细笔记

## 一、指令格式设计

### 1.1 指令的基本构成要素

指令由**操作码**和**地址码**两部分组成：

- **操作码**：指明指令执行的操作性质（如加、减、转移）
- **地址码**：指明操作数来源、结果存放地址或下条指令地址

### 1.2 地址码结构类型（按地址数量分类）

| 类型           | 格式               | 功能说明         | 应用场景                                                     |
| -------------- | ------------------ | ---------------- | ------------------------------------------------------------ |
| **零地址指令** | OP                 | 无显式操作数地址 | 1. 无需操作数的指令（如NOP、HLT） 2. 操作数隐含在堆栈中的指令（如PUSH、POP） |
| **一地址指令** | OP + A1            | 只有一个显式地址 | 1. 单操作数指令（INC、DEC） 2. 另一操作数隐含在累加器ACC中（如ADD A） |
| **二地址指令** | OP + A1 + A2       | 两个操作数地址   | 最常见格式，A1为源操作数，A2为目的操作数兼结果存放处         |
| **三地址指令** | OP + A1 + A2 + A3  | 三个操作数地址   | A1、A2为源操作数地址，A3为结果地址（如RISC指令）             |
| **多地址指令** | OP + A1 + ... + An | 多个地址字段     | 用于向量、矩阵等特殊运算                                     |

### 1.3 操作码设计技术

#### 1.3.1 定长操作码

- **特点**：操作码长度固定不变
- **优点**：译码简单、速度快，适合流水线处理
- **缺点**：指令数量受限制
- **示例**：若操作码占8位，则最多有2⁸=256条指令

#### 1.3.2 变长操作码（扩展操作码）

- **特点**：操作码长度可变，不同类型指令操作码长度不同
- **设计原则**： 使用频度高的指令分配短操作码 使用频度低的指令分配长操作码 短码不能是长码的前缀（哈夫曼编码思想）
- **实现方式**： `操作码扩展示例（假设指令字长16位）： 00×× ×××× ×××× ××××    // 4条一地址指令 01×× ×××× ×××× ×××× 10×× ×××× ×××× ×××× 11×× ×××× ×××× ×××× 1100 ×××× ×××× ××××    // 扩展为二地址指令 1101 ×××× ×××× ×××× 1101 10×× ×××× ××××    // 进一步扩展`

#### 1.3.3 操作码与地址码的权衡

- 地址码数量增加 → 操作码长度减少 → 指令功能增强但指令数减少
- 固定指令字长下的优化策略：高频指令用短地址码，低频指令用长地址码

### 1.4 指令字长设计

#### 1.4.1 定长指令字

- 所有指令长度相同
- 优点：简化指令译码，便于流水线实现
- 缺点：可能浪费存储空间
- 典型代表：RISC架构（如MIPS、ARM的32位固定长度）

#### 1.4.2 变长指令字

- 不同指令长度不同
- 优点：节省存储空间，提高代码密度
- 缺点：译码复杂，不利于流水线
- 典型代表：CISC架构（如x86指令长度1-15字节）

#### 1.4.3 指令格式设计实例

```
x86指令示例：
操作码(1-2字节) + ModR/M(1字节) + SIB(0-1字节) + 位移(0-4字节) + 立即数(0-4字节)

MIPS指令示例：
R型：6位操作码 + 5位rs + 5位rt + 5位rd + 5位shamt + 6位funct
I型：6位操作码 + 5位rs + 5位rt + 16位立即数/地址偏移
J型：6位操作码 + 26位跳转目标地址
```

## 二、指令系统设计

### 2.1 CISC与RISC设计哲学对比

| 特性           | CISC（复杂指令集计算机）       | RISC（精简指令集计算机）     |
| -------------- | ------------------------------ | ---------------------------- |
| **设计目标**   | 面向高级语言，增强单条指令功能 | 面向编译器优化，简化硬件设计 |
| **指令数量**   | 多（通常200条以上）            | 少（通常100条以内）          |
| **指令格式**   | 变长、格式多样                 | 定长、格式规整（通常2-3种）  |
| **寻址方式**   | 复杂多样（10种以上）           | 简单规整（通常≤5种）         |
| **执行时间**   | 不同指令差异大                 | 大多数指令单周期完成         |
| **实现方式**   | 微程序控制为主                 | 硬布线控制为主               |
| **寄存器数量** | 较少                           | 大量通用寄存器               |
| **典型架构**   | x86、VAX                       | MIPS、ARM、PowerPC、RISC-V   |

### 2.2 现代指令系统设计的权衡因素

#### 2.2.1 硬件成本与性能

- **简单指令系统**：硬件实现简单，但程序较长
- **复杂指令系统**：程序较短，但硬件复杂，可能降低主频

#### 2.2.2 兼容性与创新

- **向后兼容**：新处理器必须支持旧指令，限制了架构创新
- **创新设计**：放弃兼容性可获得更优设计，但需重建软件生态

#### 2.2.3 可编程性与编译优化

- **面向程序员**：提供丰富、强大的指令，便于汇编编程
- **面向编译器**：提供规整、简单的指令，便于编译优化

### 2.3 指令系统的关键技术

#### 2.3.1 流水线技术

- **RISC的关键特征**：几乎所有指令等长、执行时间相近，便于深度流水
- **流水线冒险处理**： 结构冒险：资源冲突（通过资源复制解决） 数据冒险：数据相关（通过转发、暂停解决） 控制冒险：分支预测错误（通过预测、延迟槽解决）

#### 2.3.2 寻址方式设计

- **立即寻址**：操作数在指令中
- **直接寻址**：地址在指令中
- **间接寻址**：指令中地址指向操作数地址
- **寄存器寻址**：操作数在寄存器中
- **寄存器间接**：寄存器内容为操作数地址
- **基址寻址**：基址寄存器+偏移量
- **变址寻址**：变址寄存器+基址
- **相对寻址**：PC+偏移量
- **堆栈寻址**：操作数在堆栈中

#### 2.3.3 现代架构融合趋势

- **RISC核心+CISC外层**：现代x86内部将复杂指令分解为RISC微操作
- **混合长度指令集**：如ARM的Thumb-2（16/32位混合）
- **可配置指令集**：如RISC-V的模块化扩展

## 三、程序的机器级表示

### 3.1 操作数表示与存储

#### 3.1.1 操作数类型

- **整数**：字节（8位）、半字（16位）、字（32位）、双字（64位）
- **浮点数**：单精度（32位）、双精度（64位）
- **地址/指针**：内存地址，宽度由地址空间决定
- **位字段**：对单个位或位组的操作

#### 3.1.2 操作数存储位置

1. **寄存器**：速度最快，数量有限
2. **存储器**：容量大，速度慢
3. **立即数**：编码在指令中，访问快但范围有限

### 3.2 操作类型分类

#### 3.2.1 数据传送指令

- **LOAD**：存储器→寄存器
- **STORE**：寄存器→存储器
- **MOV**：寄存器间或立即数到寄存器
- **PUSH/POP**：堆栈操作

#### 3.2.2 算术运算指令

- **加法**：ADD、ADC（带进位加）
- **减法**：SUB、SBB（带借位减）
- **乘法**：MUL、IMUL（有符号）
- **除法**：DIV、IDIV（有符号）
- **增量/减量**：INC、DEC

#### 3.2.3 逻辑运算指令

- **位运算**：AND、OR、XOR、NOT
- **移位**：算术移位（SAR、SAL）、逻辑移位（SHR、SHL）、循环移位
- **位测试与设置**：TEST、BT（位测试）、BTS（位测试并置位）

#### 3.2.4 控制转移指令

- **无条件跳转**：JMP
- **条件跳转**：基于标志位（JE/JZ、JNE/JNZ、JG、JL等）
- **子程序调用**：CALL-RET
- **中断与异常**：INT、IRET

#### 3.2.5 系统控制指令

- **特权指令**：仅在内核态执行
- **缓存控制**：WBINVD（写回并使缓存无效）
- **TLB控制**：INVLPG（使TLB项无效）

### 3.3 程序流程控制实现

#### 3.3.1 条件执行

- **条件码/标志位**：CPU状态寄存器中的位 ZF（零标志）：结果为0时置1 SF（符号标志）：结果为负时置1 CF（进位标志）：最高位有进位时置1 OF（溢出标志）：有符号溢出时置1
- **条件跳转实现**： `CMP AX, BX    ; 比较AX和BX，设置标志位 JG target     ; 如果AX>BX（有符号），跳转到target`

#### 3.3.2 循环结构

- **计数器控制循环**： `MOV CX, 10    ; 设置循环次数 loop_start:    ; 循环体    DEC CX    ; 计数器减1    JNZ loop_start  ; 不为0则继续循环`
- **条件控制循环**： `while_start:    CMP AX, BX    JE while_end    ; 条件不满足则退出    ; 循环体    JMP while_start while_end:`

#### 3.3.3 过程（函数）调用

- **调用约定**： 参数传递：寄存器 vs 堆栈 返回值存放位置 调用者保存 vs 被调用者保存寄存器
- **栈帧结构**： `高地址 | 调用者栈帧 | |------------| | 返回地址   | ← 调用时压入 | 旧帧指针   | ← 被调用者保存 | 局部变量   | | 保存寄存器 | | 参数构造区 | ← 可能用于向更深的调用传递参数 低地址`
- **进入和退出序列**： `; 进入序列（被调用者） PUSH EBP        ; 保存旧帧指针 MOV EBP, ESP    ; 建立新帧指针 SUB ESP, N      ; 为局部变量分配空间 ; 退出序列 MOV ESP, EBP    ; 释放局部变量空间 POP EBP         ; 恢复旧帧指针 RET             ; 返回`

### 3.4 数据类型与结构表示

#### 3.4.1 数组访问

- **一维数组**：`地址 = 基地址 + 索引 × 元素大小`
- **多维数组**（行主序）：`地址 = 基地址 + (行索引×列数+列索引)×元素大小`

#### 3.4.2 结构体/记录

- 连续存储，成员按声明顺序排列
- 对齐要求：多数系统要求数据类型在自然边界对齐

#### 3.4.3 指针与动态内存

- **指针变量**：存储内存地址
- **动态分配**：通过系统调用（如malloc/free）管理堆内存

### 3.5 汇编与机器码对应关系

#### 3.5.1 汇编指令到机器码

```
汇编指令：ADD EAX, 0x12345678
机器码（x86）：05 78 56 34 12
解释：
05 - ADD EAX, imm32的操作码
78 56 34 12 - 小端表示的立即数0x12345678
```

#### 3.5.2 反汇编技术

- 线性扫描：从入口点开始依次解码
- 递归下降：按控制流跟踪所有可能路径

------

## 关键总结与联系

1. **指令格式是基础**：操作码和地址码的设计决定了指令的表达能力，影响硬件实现复杂度。
2. **指令系统是桥梁**：介于硬件微架构和软件之间，CISC与RISC代表两种不同的设计权衡。
3. **机器级表示是实例化**：高级语言构造最终被翻译为指令序列，反映了指令系统的实际运用。
4. **现代趋势是融合**：纯CISC或RISC已少见，现代处理器通过内部微操作、混合长度指令等技术融合两者优点。
5. **性能是关键驱动**：所有设计决策最终服务于性能目标，包括代码密度、执行速度、功耗效率等方面。

这份详细笔记系统地梳理了指令系统的三个核心方面，从指令的格式设计基础，到整体指令系统的架构选择，再到程序在机器级别的具体表示方式，形成了完整的知识体系。
