# 数据库完整性

### 一、 数据库完整性概述

- **目标**：确保数据库中数据的**正确性**（符合现实世界语义）和**相容性**（同一对象在不同表中的数据逻辑一致）。
- **与安全性的区别**： **完整性**：防范对象是**不正确的数据**，确保数据本身符合语义。 **安全性**：防范对象是**非法用户和操作**，防止未授权存取和破坏。
- **完整性机制**： **定义机制**：提供定义完整性约束条件（规则）的方法。 **检查机制**：在数据更新（INSERT, UPDATE, DELETE）时或事务提交时自动检查约束。 **违约处理**：当违反约束时，采取拒绝（NO ACTION）、级联（CASCADE）或设为空值（SET NULL）等动作。

### 二、 完整性约束的分类与SQL实现

文档将完整性约束分为三大类，并详细说明了如何在SQL中定义。

#### 1. 实体完整性

- **定义**：要求**主码**（Primary Key）的取值唯一且非空。

- **SQL实现**：在`CREATE TABLE`中使用`PRIMARY KEY`定义。

- **检查与违约处理**：插入或更新时，DBMS自动检查主码是否唯一且非空，若违反则拒绝操作。

- **示例**（来自文档）： 

  ```SQL
  -- 例5.1：在Student表定义主码（两种方式）
  -- 列级定义
  CREATE TABLE Student(
      Sno CHAR(9) PRIMARY KEY, -- Sno是主码
      ...其他列...
  );
  -- 表级定义
  CREATE TABLE Student(
      Sno CHAR(9),
      ...其他列...,
      PRIMARY KEY(Sno) -- 在表级定义Sno为主码
  );
  
  -- 例5.2：多列主码（只能在表级定义）
  CREATE TABLE SC(
      Sno CHAR(9) NOT NULL,
      Cno CHAR(4) NOT NULL,
      Grade SMALLINT,
      PRIMARY KEY(Sno, Cno) -- Sno和Cno共同构成主码
  );
  ```

  

#### 2. 参照完整性

- **定义**：要求**外码**（Foreign Key）的取值必须是另一个表（被参照表）中主码的有效值或为空。

- **SQL实现**：在`CREATE TABLE`中使用`FOREIGN KEY ... REFERENCES ...`定义，并可指定违约处理规则（`ON DELETE/UPDATE`）。

- **违约处理**（当被参照表的数据被修改或删除时）： **拒绝 (NO ACTION / RESTRICT)**：默认策略，拒绝执行破坏完整性的操作。 **级联 (CASCADE)**：同步删除或更新参照表中的相关元组。 **设为空值 (SET NULL)**：将参照表中相关元组的外码值设为NULL。

- **示例**（来自文档）： 

  ```SQL
  -- 例5.3 & 5.4：定义SC表中的参照完整性及违约处理
  CREATE TABLE SC(
      Sno CHAR(9) NOT NULL,
      Cno CHAR(4) NOT NULL,
      Grade SMALLINT,
      PRIMARY KEY(Sno, Cno),
      FOREIGN KEY (Sno) REFERENCES Student(Sno)
          ON DELETE CASCADE   -- 当删除Student中的学生时，级联删除SC中其所有选课记录
          ON UPDATE CASCADE,  -- 当更新Student中的学号时，级联更新SC中的学号
      FOREIGN KEY (Cno) REFERENCES Course(Cno)
          ON DELETE NO ACTION -- 当删除Course中的课程时，若SC中仍有选课记录，则拒绝删除
          ON UPDATE CASCADE   -- 当更新Course中的课程号时，级联更新SC中的课程号
  );
  ```

  

#### 3. 用户定义的完整性

针对特定应用语义的约束，包括**列级约束**和**表级（元组级）约束**。

- **列级约束**：对单个列的取值限制。 **NOT NULL**：非空。 **UNIQUE**：取值唯一（但可为空）。 **CHECK**：满足指定条件。

- **表级约束**：涉及多个列之间的取值逻辑。

- **示例**（来自文档）： 

  ```SQL
  -- 例5.7：列级CHECK约束 - 性别只能为‘男’或‘女’
  CREATE TABLE Student(
      ...
      Ssex CHAR(2) CHECK(Ssex IN ('男', '女')),
      ...
  );
  
  -- 例5.8：列级CHECK约束 - 成绩在0到100之间
  CREATE TABLE SC(
      ...
      Grade SMALLINT CHECK(Grade >= 0 AND Grade <= 100),
      ...
  );
  
  -- 例5.9：表级CHECK约束 - 性别为‘男’时，名字不能以‘Ms.’开头
  CREATE TABLE Student(
      ...
      CHECK(Ssex='女' OR Sname NOT LIKE 'Ms.%')
  );
  ```

### 三、 其他完整性机制

#### 1. 完整性约束命名与修改

- **目的**：为约束命名，便于后续修改或删除。

- **SQL实现**：使用`CONSTRAINT <约束名>`子句。

- **示例**（来自文档）： 

  ```SQL
  -- 例5.10：创建命名约束
  CREATE TABLE Student(
      Sno NUMERIC(6) CONSTRAINT C1 CHECK (Sno BETWEEN 90000 AND 99999),
      Sname CHAR(20) CONSTRAINT C2 NOT NULL,
      Sage NUMERIC(3) CONSTRAINT C3 CHECK (Sage < 30),
      CONSTRAINT StudentKey PRIMARY KEY(Sno) -- 主码约束也有名字
  );
  
  -- 例5.12 & 5.13：修改约束（先删除，后增加）
  ALTER TABLE Student DROP CONSTRAINT C3; -- 删除年龄约束
  ALTER TABLE Student ADD CONSTRAINT C3 CHECK (Sage < 40); -- 添加新约束
  ```

  

#### 2. 域（Domain）约束

- **定义**：创建用户自定义的数据类型，并为该类型定义约束，可被多个列共享。

- **示例**（来自文档）：

  ```SQL
  -- 例5.15：创建性别域
  CREATE DOMAIN GenderDomain CHAR(2)
      CONSTRAINT GD CHECK (VALUE IN ('男', '女'));
  -- 使用时
  CREATE TABLE Student (
      Ssex GenderDomain, -- 直接使用自定义域，自动带有‘男女’约束
      ...
  );
  ```

  

#### 3. 断言（Assertion）

- **定义**：更一般性、涉及多表或聚集操作的复杂完整性约束。**但文档指出，因其开销大，现代数据库系统慎用**。

- **示例**（来自文档）： 

  ```SQL
  -- 例5.18：限制‘数据库’课程最多60人选修
  CREATE ASSERTION ASSE_SC_DB_NUM
      CHECK (60 >= (SELECT count(*)
                    FROM Course, SC
                    WHERE SC.Cno = Course.Cno AND Course.Cname='数据库'));

#### 4. 触发器（Trigger）★

- **定义**：由事件（增、删、改）驱动的特殊过程，用于实现比CHECK更复杂的业务规则和完整性约束。功能强大，应用广泛。

- **组成**：**触发事件** → **触发条件** → **触发动作体**。

- **类型**： **行级触发器** (`FOR EACH ROW`)：触发事件影响的每一行都会执行一次动作体。可使用`OLD`和`NEW`引用旧/新行值。 **语句级触发器** (`FOR EACH STATEMENT`)：触发事件执行后，动作体只执行一次。

- **示例**（来自文档）： 

  ```SQL
  -- 例5.21：行级触发器 - 记录成绩大幅修改
  CREATE TRIGGER SC_T
  AFTER UPDATE OF Grade ON SC -- 更新Grade列后触发
  REFERENCING
      OLD ROW AS OldTuple,
      NEW ROW AS NewTuple
  FOR EACH ROW
  WHEN (NewTuple.Grade >= 1.1 * OldTuple.Grade) -- 条件：分数增加10%以上
      INSERT INTO SC_U (Sno, Cno, OldGrade, NewGrade) -- 动作：记录到日志表
      VALUES (OldTuple.Sno, OldTuple.Cno, OldTuple.Grade, NewTuple.Grade);
  
  -- 例5.23：BEFORE行级触发器 - 自动保证教授工资不低于4000
  CREATE TRIGGER Insert_Or_Update_Sal
  BEFORE INSERT OR UPDATE ON Teacher -- 插入或更新前触发
  REFERENCING NEW ROW AS newTuple
  FOR EACH ROW
  BEGIN
      IF (newTuple.Job='教授') AND (newTuple.Sal < 4000)
      THEN newTuple.Sal := 4000; -- 在数据写入表前自动修改
      END IF;
  END;
  ```

  

### 四、 断言与触发器的比较（文档总结）

| 特性         | 断言                             | 触发器                                                     |
| ------------ | -------------------------------- | ---------------------------------------------------------- |
| **约束条件** | 要求永远为真                     | 可有条件，可能成立也可能不成立                             |
| **检查时机** | 数据变化时，在全库范围检查       | 仅在触发事件发生且条件成立时执行                           |
| **主要用途** | 仅用于完整性约束检查，违反则拒绝 | 维护完整性约束，**更用于实现业务逻辑、安全审计、主动功能** |
| **跟踪能力** | 无法跟踪更改                     | 可跟踪所有更改并执行复杂动作                               |
| **使用建议** | 检查开销高，**慎用**             | 功能强大，在现代数据库中得到很好应用                       |

### 总结

这份讲义系统地阐述了数据库完整性的方方面面：从**核心的实体、参照、用户定义完整性**的SQL定义与违约处理，到更高级的**命名约束、域、断言和触发器**机制。**触发器**因其灵活性和强大功能，是实现复杂业务规则和主动数据库系统的关键工具。文档通过大量具体的SQL示例（如定义主外码、CHECK约束、CASCADE操作、触发器逻辑等）将抽象概念具象化，是理解数据库如何保证数据正确性的优秀材料。
