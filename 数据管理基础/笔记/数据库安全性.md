# 数据库安全性

### 一、 数据库安全性概述

1. **必要性**：数据库的数据共享特性必然带来安全性问题，需防止不合法使用造成的数据泄露、更改或破坏。
2. **破坏来源与保护措施**： 非法用户 → 安全性保护（权限管理） 非法数据 → 完整性保护 各种故障或误操作 → 故障恢复 多用户的并发访问 → 并发控制
3. **不安全因素**： 非授权用户的恶意存取和破坏。 重要或敏感数据泄露。 计算机系统（硬件、OS、网络）安全环境脆弱性。
4. **安全标准**： **TCSEC/DoD85**：美国国防部制定的可信计算机系统评估准则，将安全级别划分为D、C1、C2、B1、B2、B3、A1。 **CC标准**：国际通用的信息技术安全评估准则，将安全要求分为“安全功能要求”和“安全保证要求”，并定义了EAL1至EAL7七个评估保证级。 **中国标准**：主要是GB17859-1999《计算机信息系统安全保护等级划分准则》，分为用户自主保护级至访问验证保护级共五级。

### 二、 数据库安全性控制（核心技术）

数据库管理系统（DBMS）通过多层机制保障安全，核心流程是：身份鉴别 → 存取控制 → 审计。

1. **用户身份鉴别**：系统最外层保护，方法包括： 静态口令鉴别 动态口令鉴别 生物特征鉴别（如指纹、虹膜） 智能卡鉴别

2. **存取控制**：核心安全机制，包括定义用户权限和进行合法权限检查。 
   **自主存取控制（DAC）**： 

   + **概念**：用户可以将自己拥有的存取权限自主地授予或回收给其他用户。 
   + **实现**：通过SQL的`GRANT`和`REVOKE`语句进行授权与回收。权限涉及数据库对象（模式、表、视图、列等）和操作类型（SELECT、INSERT、UPDATE等）。 
   + **特点**：灵活但可能存在“无意泄露”。

    **强制存取控制（MAC）**： 

   + **概念**：为每个**主体**（用户）和**客体**（数据对象）标记敏感度级别，系统强制执行严格的存取规则。
   +  **敏感度标记**：绝密（TS）> 机密（S）> 可信（C） > 公开（P）。
   +  **规则**： **下读**：主体许可证级别 ≥ 客体的密级时，才能**读取**。 **上写**：主体许可证级别 ≤ 客体的密级时，才能**写入**。 
   + **特点**：安全性更高，适用于军事、政府等有固定密级要求的部门。通常与DAC结合使用，先进行DAC检查，再进行MAC检查。

3. **数据库角色**： **概念**：一组权限的集合，用于简化对具有相同权限用户组的管理。 **操作**：创建角色、给角色授权、将角色授予用户、修改角色权限、回收角色。

4. **创建数据库模式的权限**： **DBA**：超级用户，拥有所有权限。 **RESOURCE**：可创建基本表和视图，但不能创建模式和用户。 **CONNECT**：仅可登录数据库并执行已有权限的操作。

### 三、 其他安全性机制

1. **视图机制**：通过对无权用户隐藏保密数据（即仅提供视图）来提供安全保护。
2. **审计**： **概念**：启用审计日志记录用户对数据库的所有操作，用于事后监控和追查。 **审计事件**：包括服务器事件、系统权限、语句事件、模式对象事件。 **命令**：`AUDIT`设置审计，`NOAUDIT`取消审计。
3. **数据加密**： **存储加密**：包括对应用透明的内核级加密和通过函数实现的非透明存储加密。 **传输加密**：包括链路加密（加密报头和报文）和端到端加密（只加密报文）。
4. **其他保护**： **推理控制**：防止用户通过可访问的低密级数据推导出高密级数据。 **隐蔽信道**：处理间接的数据传递路径。 **数据隐私保护**：保护个人数据在整个生命周期中的隐私。

### 四、 附：MySQL安全性管理SQL命令示例

文档最后列举了MySQL中与安全性管理相关的部分SQL命令，包括：

- `CREATE USER`：创建用户。
- `CREATE ROLE`：创建角色。
- `GRANT`：进行授权，支持授予具体操作权限或角色，可使用`WITH GRANT OPTION`（对象权限）或`WITH ADMIN OPTION`（系统权限/角色）允许被授权者传播权限。
- `REVOKE`：回收权限或角色，可使用`CASCADE`进行级联回收。
- 文档还以表格形式列出了MySQL中可授予的静态权限及其作用级别（全局、数据库、表、列）。
