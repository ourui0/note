## 1　实现功能

程序使用 GNU Flex、GNU Bison 和 C99 实现 C-- 语言的词法分析与语法分析。命令行接收一个源文件：输入合法时按课程要求输出语法树；出现错误时输出错误类型、行号和简要说明，不输出不完整的语法树。

• 识别标识符、关键字、运算符、分隔符、十进制整数和浮点数（含 `.5`、`43.` 这类附录 A 允许的基数形式），以及附录 A 规定的声明、结构体、函数、语句与表达式。

• 构建并先序输出语法树；非终结符标注首个词素的行号，ID、TYPE、INT 和 FLOAT 结点输出对应值，空产生式不输出。

• 报告 A 类词法错误和 B 类语法错误，并在同一文件中继续搜集位于不同行的多处错误。

• 仅实现选做 3：识别 `//` 单行注释和 `/* ... */` 块注释。未实现选做 1、2；八/十六进制整数与指数形式浮点数按附录 A 文法作为普通词素交语法层处理，天然落在错误分支上，功能边界与测试分组保持一致。

## 2　实现方法与亮点

**词素位置统一跟踪。** lexer.l 自己维护行计数器 `line_count`（在换行符规则中自增），而不是使用 Flex 的 `%option yylineno`：后者在扫描到换行符时就把行号推进到下一行，会让换行符之后的词素与它"同一行"，导致漏写分号这类错误整体后移一行。`YY_USER_ACTION` 在每个词素开始处统一维护 `token_line`（当前词素行）、`prev_token_line`（上一个词素行）和 `yy_last_token`（最近返回的词素），无论规则如何分支（关键字、数字、注释、被丢弃的非法字符），位置状态推进都一致。

**错误行号取"被读到的那个不该出现的词素"所在行。** parser.y 的 `yyerror` 按如下规则定位：

```text
if (token_line > prev_token_line && opens_new_unit(yy_last_token))
        归到 prev_token_line        // 跨行且该词素能开启新语法单元
else    取 token_line               // 否则取当前词素行
```

`opens_new_unit` 只认 `TYPE / STRUCT / RETURN / IF / WHILE / LC` 六个词素。于是"漏写分号"这类错误落在**缺分号的那一行**（如 `int z` 后缺分号、下一行是 `return`，报 `int z` 所在行）；若下一行是缩进后的语句，则按当前行报告，与判题样例一致。

**每个语法单元一条 `error` 产生式。** 17 个语法单元（`ExtDefList`、`ExtDef`、`ExtDecList`、`Specifier`、`StructSpecifier`、`OptTag`、`Tag`、`VarDec`、`FunDec`、`VarList`、`ParamDec`、`CompSt`、`Def`、`DecList`、`Dec`、`Exp`、`Args`）各带一条 `| error { $$ = NULL; }`。出错时该单元立刻归约为空结点，分析器在**出错那一行内**完成恢复，不必为寻找同步点向后丢弃词素，因此后续各行的错误能各自独立报出。刻意不写 `yyerrok`，让 Bison 正常的错误报告流程完整走一遍；`Stmt`、`DefList`、`StmtList` 不挂 `error`，其错误由内部单元消化。

**诊断立即报告、同行去重。** Bison 每次发现错误都会调用 `yyerror`，`yyerror` 当场写诊断，不把错误"挂起"到恢复动作里再输出。同一行只保留第一条诊断（first-error-wins），不区分 A/B 优先级——这与 OJ"每行一条"的判定口径一致。

**注释与词法边界。** 块注释使用 COMMENT 独占状态，注释内换行同样计入 `line_count`，因此注释之后的行号仍然准确；遇到第一个 `*/` 返回普通状态，文件结束时仍未闭合则把 A 类诊断定位到注释起始行；普通状态下的非法字符由兜底规则报 A 类错误。

**语法树。** parser.y 完整表达附录 A 文法，显式设置赋值/逻辑/关系/算术/一元/访问运算的优先级与结合性；`UMINUS` 区分一元负号，`LOWER_THAN_ELSE` 保证 `else` 与最近的 `if` 匹配。统一建树函数忽略空结点、按原文法顺序连接子结点；空文件（或只有注释、空白）仍输出一个无子结点的 `Program` 根结点。所有结点纳入统一分配链，结束时一次性释放。

## 3　编译与运行

提交包内的源码位于 Code 目录，包括 parser.h、lexer.l、parser.y 和 parser.c。编译环境需要 GCC（支持 C99）、GNU Flex、GNU Bison，以及 Flex/Yacc 运行库 libfl、liby。建议在课程指定的 Linux 环境中编译。

将课程提供的 Makefile_ref 复制为 Code/Makefile，再执行：

```text
cd Code
make
./parser input.cmm
```

make 依次调用 Flex 生成 lex.yy.c、调用 Bison 生成 syntax.tab.c 与 syntax.tab.h、编译 parser.c 和 syntax.tab.c，最后链接得到 parser。lexer.l 引用 Bison 生成的 syntax.tab.h，parser.y 在生成的分析器中纳入 lex.yy.c，与 Makefile_ref 的构建方式一致。

运行时必须且只能给出一个 C-- 源文件。语法树和 A/B 类错误均写入 stdout，stderr 不输出任何内容；按照 OJ 要求，只要程序完成分析就返回 0；参数数量错误或无法打开文件时返回 2。清理中间文件可执行 make clean。

## 4　正确性检查

• 用课程给出的 A/B/C/D/E 共 20 余个用例逐条核对错误类型、行号序列与语法树输出，全部通过；浮点数（含 `.5`、`43.`、长小数）的语法树逐字节一致。

• 以另一份满分实现为参照做差分测试：把合法程序按删除、插入、替换、重复、交换等变异方式随机生成约 1200 条含错输入，比较错误类型/行号序列与语法树，结果完全一致；差异只在"仅注释文件"这类无语素输入上出现，修正根结输出后亦一致。

• 边界输入：空文件、纯注释、纯空白、CRLF 换行、文件末尾无换行、未闭合块注释、非法字符、300 层括号与 200 层花括号嵌套、500 条语句的长程序，均正常结束（返回 0、stderr 为空）。

## 5　总结

本实验完成了 C-- 词法分析、语法分析、语法树输出与多错误诊断。实现的关键在于把"词素位置跟踪—错误行号判定—错误恢复"三件事分层：词法层用显式行计数器统一维护位置，语法层只决定"这个错误属于哪一行"，恢复动作（每个语法单元一条 `error` 产生式）只负责让分析在本行继续。三者配合后，单处错误与多行多处错误都能给出稳定的错误类型与行号。选做部分实现选做 3 的两类注释，未实现的选做 1、2 词素交由文法自然报错。
