## 1. 网络体系结构与分层

### 1.1 什么是网络体系结构

网络体系结构是计算机网络的分层结构和协议集合。

它规定：

- 网络被分成哪些层。
- 每一层负责什么功能。
- 相邻层之间通过什么接口交互。
- 同一层的通信实体之间使用什么协议。
- 数据如何在发送端逐层封装，在接收端逐层解封装。

一句话：网络体系结构就是“网络系统如何分层、每层干什么、层与层之间如何配合”的总体设计。

### 1.2 为什么要分层

分层的目的：

- 降低复杂度：每层只解决一类问题。
- 模块化：某一层内部实现变化，不必影响其他层。
- 复用：上层可以复用下层提供的服务。
- 标准化：不同厂商设备只要遵守协议，就能互联。

代价：

- 层间可能有重复功能，例如链路层和运输层都可能做差错控制。
- 有些优化跨层更难做。

### 1.3 层与层之间怎么调用

发送端自上而下调用：

```text
应用层数据
-> 运输层封装成 segment
-> 网络层封装成 datagram
-> 链路层封装成 frame
-> 物理层变成 bit / signal 发送
```

接收端自下而上交付：

```text
物理层收到 signal
-> 链路层取出 frame
-> 网络层取出 datagram
-> 运输层取出 segment
-> 应用层得到 message
```

每一层看起来像是在和对方同层通信，实际数据必须通过下层传输。

## 2. OSI、TCP/IP 与经典模型

### 2.1 OSI 七层模型

OSI 是理论参考模型，共七层：

| 层次 | 名称 | 主要功能 |
|---|---|---|
| 7 | 应用层 | 为应用程序提供网络服务 |
| 6 | 表示层 | 数据表示、编码、加密、压缩 |
| 5 | 会话层 | 会话建立、管理、同步 |
| 4 | 运输层 | 进程到进程通信，可靠传输、流量控制 |
| 3 | 网络层 | 主机到主机通信，路由和转发 |
| 2 | 数据链路层 | 相邻节点传输，成帧、差错检测、MAC |
| 1 | 物理层 | 比特在介质上传输 |

### 2.2 TCP/IP 模型

TCP/IP 是 Internet 实际使用的协议体系，常按五层理解：

| TCP/IP 层次 | 对应协议或技术 |
|---|---|
| 应用层 | HTTP、DNS、SMTP、FTP |
| 运输层 | TCP、UDP |
| 网络层 | IP、ICMP、路由协议 |
| 链路层 | Ethernet、WiFi、PPP、ARP |
| 物理层 | 光纤、双绞线、无线电、同轴电缆 |

### 2.3 OSI 和 TCP/IP 的区别

重点区别：

- OSI 是七层理论模型，TCP/IP 是实际广泛部署的协议体系。
- TCP/IP 没有单独保留表示层和会话层，这些功能通常并入应用层或由应用自己处理。
- OSI 更强调清晰分层，TCP/IP 更强调工程可用和互联互通。
- Internet 的核心是 IP，形成“IP 沙漏”：上面很多应用，下面很多链路技术，中间统一用 IP。

## 3. 物理层

### 3.1 物理层解决什么问题

物理层解决的是：如何把比特变成物理信号，并通过传输介质发送到相邻节点。

它关注：

- bit 如何编码成电信号、光信号或无线电波。
- 传输速率是多少。
- 信号如何同步。
- 传输介质是什么。
- 接口、电气特性、机械特性。

物理层不关心 IP 地址、端口号、可靠传输、路由选择。

### 3.2 常见传输介质比较

| 介质 | 特点 | 优点 | 缺点 |
|---|---|---|---|
| 双绞线 | 铜线，局域网常用 | 便宜、部署方便 | 距离和抗干扰能力有限 |
| 同轴电缆 | 早期以太网、有线电视 | 抗干扰较好 | 现在局域网中较少用 |
| 光纤 | 用光信号传输 | 高带宽、低误码、远距离、抗电磁干扰 | 成本和施工要求较高 |
| 无线电 | WiFi、蜂窝网络 | 移动性强、无需布线 | 易受干扰、衰减、多径影响 |
| 卫星链路 | 远距离覆盖 | 覆盖广 | 传播时延大，地球同步卫星约数百 ms |

### 3.3 物理层相关时延

网络时延主要包括四类：

| 时延 | 含义 | 公式或影响因素 |
|---|---|---|
| 传输时延 | 把整个分组推入链路的时间 | `d_trans = L / R` |
| 传播时延 | 一个比特在介质中传播到对端的时间 | `d_prop = distance / speed` |
| 排队时延 | 分组在队列里等待的时间 | 取决于拥塞程度 |
| 处理时延 | 路由器或交换机处理分组的时间 | 查表、检查首部等 |

易混点：

- 传输时延看分组长度和链路速率。
- 传播时延看距离和信号传播速度。
- 提高带宽能降低传输时延，但不能消除传播时延。

## 4. 数据链路层

### 4.1 为什么引入数据链路层

网络层负责端到端路径上的 datagram 传输，但实际发送必须一跳一跳经过相邻节点。

链路层解决的问题是：

```text
如何在一条具体链路上，把网络层 datagram 从一个节点交给相邻节点？
```

### 4.2 链路层干了什么事

链路层主要功能：

- Framing：把网络层 datagram 封装成 frame。
- Link access：在共享介质上决定谁可以发送。
- MAC addressing：用 MAC 地址标识本地链路接口。
- Error detection：差错检测，如 CRC。
- Error correction：某些场景下纠错。
- Reliable delivery：某些链路上做相邻节点可靠交付。
- Flow control：相邻节点之间做流量控制。

### 4.3 链路层丢帧和差错控制

链路层常用差错检测：

- 奇偶校验。
- Internet checksum。
- CRC。

收到错误 frame 后常见处理：

- 直接丢弃。
- 如果链路层提供可靠交付，则通过 ACK、NAK、重传恢复。

注意：

- Ethernet 通常只检测错误并丢弃错误帧，不做可靠重传。
- WiFi 因为无线误码率高，常在链路层使用 ACK 和重传。
- 端到端可靠性仍然主要由 TCP 提供。

### 4.4 广播信道

广播信道是多个节点共享同一个通信介质。

特点：

- 一个节点发送，其他节点都可能听到。
- 多个节点同时发送会发生碰撞。
- 必须有 MAC 协议协调发送。

典型 MAC 协议分类：

- 信道划分：TDMA、FDMA、CDMA。
- 随机访问：ALOHA、CSMA、CSMA/CD、CSMA/CA。
- 轮流访问：polling、token passing。

## 5. Ethernet、CSMA/CD 与 ARP

### 5.1 以太网帧

Ethernet frame 主要字段：

| 字段 | 作用 |
|---|---|
| Preamble | 同步接收方时钟 |
| Destination MAC | 目的 MAC 地址 |
| Source MAC | 源 MAC 地址 |
| Type | 上层协议类型，如 IP、ARP |
| Data | 承载上层数据 |
| CRC | 差错检测 |

重点：

- MAC 地址用于本地链路交付。
- IP 地址用于跨网络寻址和路由。
- 每一跳 MAC 地址会变，IP 源/目的地址通常端到端保持不变。

### 5.2 以太网冲突检测 CSMA/CD

CSMA/CD 是 Carrier Sense Multiple Access with Collision Detection。

工作过程：

1. 发送前监听信道，空闲则发送。
2. 发送过程中继续检测碰撞。
3. 如果检测到碰撞，立即停止发送。
4. 发送 jam signal。
5. 执行二进制指数退避。
6. 等待随机时间后重传。

### 5.3 CSMA/CD 最短帧长

最短帧长的原因：发送方必须在“还没发完帧”的时候检测到最远端碰撞。

条件：

```text
帧发送时间 >= 2 × 最大传播时延
L_min / R >= 2τ
L_min >= 2Rτ
```

其中：

- `L_min`：最短帧长，单位 bit。
- `R`：链路速率，单位 bit/s。
- `τ`：单程最大传播时延。

经典 10 Mbps Ethernet：

- slot time = 512 bit times。
- 最小帧长 = 512 bit = 64 Byte。

### 5.4 ARP 协议

你写的 AIP 应该是 ARP。

ARP 是 Address Resolution Protocol，用于在同一 LAN 中把 IP 地址解析成 MAC 地址。

ARP 功能：

```text
已知目的 IP 地址，查询对应 MAC 地址
```

过程：

1. 主机查 ARP 表。
2. 若没有映射，广播 ARP request。
3. 目标主机收到后，单播 ARP reply。
4. 发送方把 IP-MAC 映射缓存到 ARP 表。

跨子网通信时：

- 主机不会 ARP 远端主机 MAC。
- 主机 ARP 默认网关的 MAC。
- frame 目的 MAC 是第一跳路由器接口 MAC。
- IP datagram 的目的 IP 仍是最终目标主机 IP。

### 5.5 CRC 计算

CRC 是链路层常见差错检测方法。

给定：

- 数据 `D`。
- 生成多项式对应的比特串 `G`。
- `G` 长度为 `r+1`，则 CRC 余数 `R` 长度为 `r` bit。

发送方要找到 `R`，使：

```text
D × 2^r + R
```

能够被 `G` 模 2 整除。

计算步骤：

1. 在 `D` 后面补 `r` 个 0。
2. 用补 0 后的串对 `G` 做模 2 除法。
3. 除法中的减法就是异或 XOR，不借位。
4. 得到的 `r` bit 余数就是 `R`。
5. 发送 `D + R`。

接收方再用收到的完整比特串除以 `G`：

- 余数为 0：认为未检测到错误。
- 余数非 0：检测到错误。

### 5.6 Slotted ALOHA 效率

Slotted ALOHA 的基本假设：

- 时间被划分成 slot。
- 一个 frame 正好占一个 slot。
- 节点只能在 slot 开始时发送。
- 如果多个节点同一 slot 发送，就碰撞。

若有 `N` 个活跃节点，每个节点在某 slot 发送概率为 `p`。

某个指定节点成功发送概率：

```text
p(1-p)^(N-1)
```

任意一个节点成功发送概率，也就是效率：

```text
N p (1-p)^(N-1)
```

最大化时：

```text
p = 1/N
```

当 `N -> ∞`：

```text
最大效率 -> 1/e ≈ 0.37
```

### 5.7 交换机自学习

Ethernet switch 是链路层设备。

交换机维护 switch table：

```text
MAC 地址 -> 接口 -> 时间戳
```

收到一个 frame 后：

1. 根据源 MAC 地址学习：这个 MAC 在入端口方向。
2. 查目的 MAC 地址。
3. 如果目的 MAC 在表中，且输出端口不同，则转发到对应端口。
4. 如果目的 MAC 在表中，但输出端口就是入端口，则过滤，不转发。
5. 如果目的 MAC 不在表中，则 flood，向除入端口外的所有端口广播。

考试题中如果交换机表初始为空，要按事件顺序一步步更新表，再判断每个 frame 是 flood、forward 还是 filter。

## 6. 网络层

### 6.1 网络层干什么

网络层负责把分组从源主机送到目的主机。

两个核心功能：

- Forwarding：转发，路由器本地查表，把分组从输入端口送到输出端口。
- Routing：路由，计算从源到目的地的路径，生成转发表。

### 6.2 IP 提供什么服务

IP 提供 best-effort service，尽力而为服务。

它不保证：

- 分组一定到达。
- 分组按序到达。
- 分组不重复。
- 分组时延有上界。
- 带宽有保证。

它只尽力转发 datagram。

可靠性、顺序、重传等通常由 TCP 或应用层实现。

### 6.3 IP 里的 ICMP

你写的 ICNP 应该是 ICMP。

ICMP 是 Internet Control Message Protocol，用于传递网络层控制和错误信息。

常见用途：

- 目的不可达。
- TTL expired。
- ping 使用 ICMP echo request / echo reply。
- traceroute 利用 TTL 和 ICMP 找出路径上的路由器。

ICMP 消息封装在 IP datagram 中。

### 6.4 IPv4 首部重点

常见字段：

- Source IP address。
- Destination IP address。
- TTL：每经过一个路由器减 1，为 0 时丢弃并可返回 ICMP。
- Protocol：指明上层是 TCP、UDP、ICMP 等。
- Header checksum：只校验 IP 首部。
- Fragmentation 相关字段：用于分片与重组。

### 6.5 最长前缀匹配

路由器查转发表时，如果多个表项都匹配目的 IP，选择前缀最长的那个。

原因：

- 前缀越长，匹配范围越小。
- 前缀越长，路由越具体。

例子：

```text
目的地址匹配 200.23.16.0/20
也匹配 200.23.18.0/23
选择 /23
```

因为 `/23` 比 `/20` 更具体。

### 6.6 子网划分

CIDR 表示：

```text
a.b.c.d/x
```

含义：

- 前 `x` bit 是网络前缀。
- 后 `32 - x` bit 是主机位。
- 地址块大小是 `2^(32-x)`。

一个子网可用主机地址通常是：

```text
2^(主机位数) - 2
```

减去：

- 全 0：网络地址。
- 全 1：广播地址。

边界条件：

- 子网块大小必须是 2 的幂。
- 子网起始地址必须对齐块大小。
- 分配时通常从大需求到小需求。
- 需要 `n` 个接口时，要找最小的 `2^k - 2 >= n`，再确定前缀 `/ (32-k)`。

例子：

```text
需要 60 个接口：
2^5 - 2 = 30 不够
2^6 - 2 = 62 够
所以主机位至少 6 位，前缀至少 /26
```

### 6.7 路由表计算与填写

转发表基本形式：

| 目的前缀 | 输出端口 / 下一跳 |
|---|---|
| 10.0.1.0/24 | interface 1 |
| 10.0.2.0/24 | interface 2 |
| 0.0.0.0/0 | default gateway |

填写思路：

1. 对直连网络，下一跳为空或直接写输出接口。
2. 对非直连网络，下一跳写相邻路由器地址。
3. 如果多条路由匹配同一目的地址，按最长前缀匹配。
4. 不知道具体目的时走默认路由 `0.0.0.0/0`。

### 6.8 路由聚合

路由聚合是把多个连续地址块合并成一个更短前缀，减少路由表规模。

能聚合的条件：

- 地址块连续。
- 块大小相同或能形成 2 的幂。
- 起始地址满足聚合边界。
- 聚合后不会错误覆盖不属于自己的地址，或有更具体路由纠正。

例子：

```text
200.23.16.0/24
200.23.17.0/24
200.23.18.0/24
200.23.19.0/24
```

可以聚合为：

```text
200.23.16.0/22
```

### 6.9 NAT

NAT 是 Network Address Translation。

作用：

- 内网使用私有地址。
- 出公网时转换成公网地址。
- 节省 IPv4 公网地址。
- 隐藏内部网络结构。

NAPT 会同时转换 IP 地址和端口。

出站转换例子：

```text
内网：192.168.1.10:3345 -> 8.8.8.8:53
NAT 后：203.0.113.5:50001 -> 8.8.8.8:53
```

NAT 表记录：

```text
203.0.113.5:50001 <-> 192.168.1.10:3345
```

回包到达公网地址和端口后，NAT 根据表项改回内部地址和端口。

## 7. 路由算法

### 7.1 链路状态算法 LS

基本思想：

- 每个路由器知道完整网络拓扑和所有链路代价。
- 每个路由器以自己为源点运行 Dijkstra 算法。
- 得到最短路径树。
- 根据最短路径树填写转发表。

Dijkstra 符号：

- `N'`：已经确定最短路径的节点集合。
- `D(v)`：当前从源点到 v 的最短路径估计。
- `p(v)`：当前最短路径中 v 的前驱节点。
- `c(x,y)`：x 到 y 的链路代价。

算法步骤：

```text
初始化 N' = {u}
对每个节点 v：
    如果 v 与 u 相邻，D(v)=c(u,v)
    否则 D(v)=∞

循环：
    选择不在 N' 中且 D(w) 最小的 w
    把 w 加入 N'
    用 w 更新它邻居 v 的 D(v)
    D(v)=min(D(v), D(w)+c(w,v))
```

考试计算：每轮找最小 D，加入集合，再更新邻居。

### 7.2 距离矢量算法 DV

核心思想：

- 每个节点只知道到邻居的链路代价。
- 每个节点维护自己到所有目的地的距离向量。
- 节点只和邻居交换距离向量。
- 根据 Bellman-Ford 方程迭代更新。

Bellman-Ford 方程：

```text
D_x(y) = min_v { c(x,v) + D_v(y) }
```

含义：

- x 要去 y。
- x 可以先走到某个邻居 v。
- 总代价 = x 到 v 的代价 + v 到 y 的估计代价。
- 在所有邻居 v 中选最小。

DV 的特点：

- 分布式。
- 异步。
- 迭代。
- 好消息传播快。
- 坏消息传播慢，可能出现 count-to-infinity。

### 7.3 LS 与 DV 对比

| 项目 | Link State | Distance Vector |
|---|---|---|
| 信息范围 | 全局拓扑 | 只知道邻居和邻居通告 |
| 典型算法 | Dijkstra | Bellman-Ford |
| 交换内容 | 链路状态 | 距离向量 |
| 计算位置 | 每个节点独立计算全局最短路 | 节点根据邻居信息迭代 |
| 问题 | 开销、振荡 | 环路、坏消息慢 |

### 7.4 OSPF、RIP、BGP 的归属

作业里常考“某路由器从哪个协议学到某前缀”。

记忆表：

| 协议 | 类型 | 使用范围 | 核心特点 |
|---|---|---|---|
| RIP | Distance Vector | AS 内部，Intra-AS | 基于跳数，和邻居交换距离向量 |
| OSPF | Link State | AS 内部，Intra-AS | 泛洪链路状态，每台路由器运行 Dijkstra |
| eBGP | Path Vector | AS 之间，Inter-AS | 不同 AS 的边界路由器之间传播前缀可达性 |
| iBGP | Path Vector | 同一 AS 内部 | 在 AS 内传播从 eBGP 学到的外部前缀 |

判断原则：

- 同一 AS 内部路由器之间学内部路径：看该 AS 运行 RIP 还是 OSPF。
- 跨 AS 边界学习外部前缀：用 eBGP。
- 同一 AS 内把外部前缀传播给其他路由器：用 iBGP。

## 8. 运输层

### 8.1 为什么引入运输层

网络层提供主机到主机通信。

运输层提供进程到进程通信。

它通过端口号把数据交给正确应用进程。

运输层主要功能：

- 复用与分用。
- 可靠数据传输。
- 流量控制。
- 拥塞控制。
- 连接管理。

UDP 提供简单的无连接服务。

TCP 提供可靠、有序、字节流服务。

### 8.2 端口号、复用与分用

运输层使用端口号把数据交给正确进程。

UDP socket 通常由二元组标识：

```text
(目的 IP, 目的端口)
```

TCP socket 通常由四元组标识：

```text
(源 IP, 源端口, 目的 IP, 目的端口)
```

Telnet 默认服务器端口：

```text
23
```

两个客户端 A、B 同时连接同一服务器 S 的 Telnet 服务时：

- 目的端口通常都是 23。
- 源端口由客户端临时选择，通常不同。
- 如果 A、B 是不同主机，即使源端口碰巧相同，TCP 四元组仍不同。
- 如果 A、B 在同一主机，同一时间连接同一服务器同一端口，则源端口必须不同，否则四元组冲突。

### 8.3 UDP checksum

UDP checksum 用于检测 UDP segment 中的比特错误。

计算思想：

- 把数据按 16 bit 分组。
- 使用反码加法求和。
- 进位回卷加到低位。
- 最后对和取反，得到 checksum。

接收方把收到的数据和 checksum 一起求和：

- 如果结果全 1，认为未检测到错误。
- 如果不是全 1，检测到错误。

注意：

- checksum 匹配不代表一定没有错误。
- 某些错误模式可能无法被检测出来。
- 所以它是差错检测，不是绝对正确性证明。

### 8.4 可靠传输通过什么机制实现

可靠传输常用机制：

- checksum：检测差错。
- ACK：确认收到。
- NAK：显式否定确认，部分协议使用。
- sequence number：序号，用于检测丢失、重复和乱序。
- timer：超时计时器。
- retransmission：超时或收到重复 ACK 后重传。
- sliding window：允许流水线发送，提高利用率。

TCP 主要依靠：

- 序号。
- 累积确认。
- 超时重传。
- 快速重传。
- 校验和。
- 滑动窗口。

### 8.5 TCP 序列号和确认号

TCP 是字节流协议。

序列号：

- TCP sequence number 是 segment 中第一个数据字节的编号。

确认号：

- ACK number 表示接收方期望收到的下一个字节编号。
- TCP 使用 cumulative ACK。

例子：

```text
发送方发送 seq=100，长度=50 字节
接收方正确收到后，返回 ACK=150
```

含义：150 之前的字节都已收到，下一个想要 150。

### 8.6 累计确认

累计确认的意思：

- ACK n 表示 n 之前的所有字节都已经按序收到。
- 如果中间缺一个 segment，后面即使到了，也仍然重复确认缺失位置。

例子：

```text
收到 0-99，ACK=100
丢了 100-199
收到了 200-299
仍然 ACK=100
```

重复 ACK 可以触发快速重传。

### 8.7 超时重传和 ACK

超时重传：

1. 发送 segment 后启动 timer。
2. 如果在超时前收到 ACK，取消或更新 timer。
3. 如果超时还没收到 ACK，重传最早未确认 segment。

TCP 超时时间基于 RTT 估计：

```text
EstimatedRTT = (1 - α) EstimatedRTT + α SampleRTT
```

常见：

```text
α = 0.125
```

TimeoutInterval 通常还会考虑 RTT 波动。

如果题目给出多个样本 RTT，按展开式：

```text
EstimatedRTT_n
= (1-α)^n EstimatedRTT_0
  + α SampleRTT_n
  + α(1-α) SampleRTT_{n-1}
  + ...
  + α(1-α)^{n-1} SampleRTT_1
```

这叫指数加权移动平均，越新的样本权重越大，越旧的样本权重按指数衰减。

### 8.8 GBN 协议

GBN 是 Go-Back-N。

特点：

- 发送方窗口大小为 N。
- 允许连续发送最多 N 个未确认分组。
- 接收方只按序接收。
- 接收方使用累计 ACK。
- 一旦某个分组丢失，之后到达的乱序分组会被丢弃。
- 超时后，发送方从丢失分组开始回退重传。

GBN 适合记忆：

```text
接收方很简单，发送方可能重传很多。
```

### 8.9 GBN 最大速率 / 利用率

设：

- `N`：发送窗口大小。
- `L`：分组长度，单位 bit。
- `R`：链路速率，单位 bit/s。
- `d_prop`：单程传播时延。
- `d_trans = L/R`：传输时延。
- `a = d_prop / d_trans`。

发送方利用率近似：

```text
U = min(1, N / (1 + 2a))
```

吞吐量：

```text
Throughput = U × R
```

另一种常用窗口吞吐量写法：

```text
Throughput ≈ min(R, W × L / RTT)
```

其中 `W` 是窗口中的分组数。

### 8.10 TCP 窗口、吞吐量和带宽时延积

带宽时延积 BDP：

```text
BDP = R × RTT
```

含义：链路“管道里”最多能容纳多少 bit。

如果 TCP 想跑满链路，窗口至少要接近：

```text
W >= R × RTT
```

如果用报文段数量表示窗口：

```text
窗口报文段数 >= R × RTT / MSS
```

单条 TCP 连接在拥塞避免中，窗口在丢包后通常从 `W/2` 线性增长到 `W`，所以平均窗口约为：

```text
3W/4
```

平均吞吐量可粗略写成：

```text
平均吞吐量 ≈ 平均窗口 / RTT
```

### 8.11 窗口相关：什么时候降为 1

TCP 拥塞窗口 `cwnd` 的变化：

- 慢启动：每 RTT 大约翻倍增长。
- 拥塞避免：每 RTT 线性增长约 1 MSS。
- 出现超时：`ssthresh = cwnd/2`，`cwnd = 1 MSS`。
- TCP Tahoe：收到 3 个冗余 ACK 也把 `cwnd` 降为 1 MSS。
- TCP Reno：收到 3 个冗余 ACK 后快速重传/快速恢复，通常不降到 1，而是降到约一半。

考试问“什么时候窗口降为 1”，优先答：

```text
发生超时 timeout 时，拥塞窗口降为 1 MSS。
```

如果题目指定 Tahoe，则三重冗余 ACK 也降为 1。

### 8.12 TCP Reno、Tahoe 与 AIMD

TCP Reno：

- 慢启动阶段：`cwnd` 指数增长。
- 拥塞避免阶段：`cwnd` 线性增长。
- 3 个冗余 ACK：认为轻度丢包，快速重传，`ssthresh = cwnd/2`，`cwnd` 降到约一半并快速恢复。
- timeout：认为拥塞更严重，`ssthresh = cwnd/2`，`cwnd = 1 MSS`。

TCP Tahoe：

- 无论 timeout 还是 3 个冗余 ACK，通常都把 `cwnd` 降到 1 MSS，重新慢启动。

AIMD：

- Additive Increase：没有拥塞时，每 RTT 窗口加性增加。
- Multiplicative Decrease：检测到拥塞时，窗口乘性减小，通常减半。

公平性注意：

- 如果两个连接 RTT 相同，AIMD 会趋向公平共享瓶颈带宽。
- 如果 RTT 不同，RTT 小的连接增长更快，可能获得更多带宽。

### 8.13 流量控制和拥塞控制区别

| 项目 | 流量控制 | 拥塞控制 |
|---|---|---|
| 保护对象 | 接收方缓冲区 | 网络 |
| 典型变量 | rwnd | cwnd |
| 问题 | 发送太快，接收方处理不了 | 网络中路由器队列拥塞 |
| TCP 发送窗口 | 受两者共同限制 | `send window = min(rwnd, cwnd)` |

## 9. 应用层：给一个应用时每层干什么

以“浏览器访问一个网页”为例：

```text
用户访问 http://www.example.com
```

### 9.1 应用层

应用层做：

- 浏览器生成 HTTP request。
- 如果只有域名，先用 DNS 查询 IP 地址。
- HTTP 定义请求和响应格式。

涉及协议：

- HTTP。
- DNS。

### 9.2 运输层

运输层做：

- HTTP 通常交给 TCP。
- TCP 建立连接，三次握手。
- TCP 把应用数据看成字节流。
- TCP 使用端口号区分进程。
- TCP 提供可靠、有序交付。

典型端口：

- HTTP：80。
- HTTPS：443。
- DNS：53，通常 UDP，也可 TCP。

### 9.3 网络层

网络层做：

- 把 TCP segment 封装进 IP datagram。
- 填写源 IP 和目的 IP。
- 路由器根据目的 IP 做最长前缀匹配。
- 每一跳选择下一跳转发。
- TTL 每跳减 1。

涉及：

- IP。
- ICMP 可能用于错误报告。
- 路由表由路由协议计算。

### 9.4 链路层

链路层做：

- 把 IP datagram 封装成 Ethernet frame 或 WiFi frame。
- 使用 MAC 地址在当前链路交付。
- 如果不知道下一跳 MAC，用 ARP 查询。
- 使用 CRC 做差错检测。

注意：

- 如果目的主机不在同一子网，链路层目的 MAC 是默认网关 MAC。
- 每一跳都会重新封装链路层 frame。
- IP 源/目的地址通常端到端不变。

### 9.5 物理层

物理层做：

- 把 frame 中的 bit 编码成电信号、光信号或无线信号。
- 通过双绞线、光纤、无线电等介质传输。

### 9.6 一句话总流程

```text
HTTP 请求
-> TCP 可靠字节流
-> IP 尽力而为转发
-> Ethernet/WiFi 本地链路交付
-> 物理层发送比特信号
```

## 10. 高频易混点

- 网络体系结构不是单个协议，而是分层结构和协议集合。
- OSI 是七层理论模型，TCP/IP 是 Internet 实际体系。
- 传输时延是把分组推上链路，传播时延是比特在介质中传播。
- MAC 地址用于本地链路，IP 地址用于跨网络路由。
- ARP 是 IP 到 MAC 的解析，只在同一 LAN 中工作。
- IP 是 best effort，不保证可靠。
- ICMP 是网络层控制报文，封装在 IP 中。
- 最长前缀匹配选最具体的路由。
- 子网划分先算主机位，再确定前缀长度。
- NAT 转换地址，NAPT 同时转换地址和端口。
- LS 用全局拓扑和 Dijkstra，DV 用邻居距离向量和 Bellman-Ford。
- TCP 序号按字节编号，不是按 segment 编号。
- ACK 号表示“下一个期望字节”。
- GBN 接收方丢弃乱序分组，发送方超时后回退重传。
- TCP 超时一般使拥塞窗口降为 1 MSS。
- 应用层给数据语义，运输层管进程间传输，网络层管主机间路径，链路层管相邻节点，物理层管信号。
