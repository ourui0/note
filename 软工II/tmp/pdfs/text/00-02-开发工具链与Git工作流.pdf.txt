根因分析：DevOps 流程的系统性缺失
直接原因：Channel File 291 包含逻辑错误，触发 W indows 内核崩溃——⽽这个⽂件被同时推送给了全球所有设备
深层原因：
⽆分阶段发布（Staged Rollout）：更新同时推向所有设备，没有⾦丝雀发布、灰度验证
测试覆盖不⾜：内容配置更新的测试标准低于内核驱动，未覆盖触发场景
⽆⾃动回滚：更新⼀旦推送，发现问题后⽆法远程撤回
修复成本极⾼：蓝屏后系统⽆法远程操作，只能⼈⼯逐台处理
今天学什么：
Git（版本追踪 + 可回滚）+ CI/CD 流⽔线（分阶段测试部署）+ Vercel（⾃动化 + 回滚）← 正是防⽌上述灾难的现代⼯具

DevO ps 是什么？
DevO ps = 开发（Dev）+ 运维（Ops）+ ⽂化/⼯具/实践
打破开发团队与运维团队之间的壁垒，让软件交付更快、更稳定
传统模式（Knight Capital 时代）：
开发写完代码  → 扔给运维  → 运维⼿动部署  → 出问题互相推责
DevO ps 模式（现代）：
代码提交  → ⾃动测试  → ⾃动构建  → ⾃动部署  → 监控反馈  → 持续改进
   ↑_______________________ 持续循环（ Infinity Loop ） _________________↑
核⼼价值：Knight Capital 如果有⾃动化部署流⽔线，旧代码绝不可能悄悄留在⼀台服务器上

Git 的四个区域
⼯作区（ Working Directory ）
    ↓  git add
暂存区（ Index / Staging Area ）        ← " 准备提交 " 的快照
    ↓  git commit
本地仓库（ Local Repository ）           ← 完整的版本历史，存在  .git ⽬录
    ↓  git push
远程仓库（ Remote Repository ）          ← GitHub / GitLab 上的副本，团队共享
    ↑  git pull / git fetch
类⽐：
⼯作区 = 你的桌⾯草稿纸
暂存区 = 你决定要装进信封的内容
本地仓库 = 你⾃⼰的档案柜（有完整历史）
远程仓库 = 办公室公⽤的云端⽂件柜

6 个最常⽤的 Git 命令
# 1. 克隆远程仓库到本地
git clone https://github.com/username/repo.git
# 2. 将⽂件添加到暂存区（准备提交）
git add filename.py        # 指定⽂件
git add .                  # 当前⽬录全部⽂件
# 3. 提交到本地仓库（附上有意义的提交信息！）
git commit -m "feat: 添加⽤户登录功能 "
# 4. 推送到远程仓库
git push origin main
# 5. 从远程仓库拉取最新代码（ = fetch + merge ）
git pull origin main
# 6. 切换分⽀  / 查看分⽀
git checkout -b feature/login   # 创建并切换到新分⽀
git checkout main               # 切换回主分⽀

--- PAGE 12 ---
查看与撤销：⽇常必备命令
# ── 查看状态  ──────────────────────────────────
git status          # 查看⼯作区和暂存区的变动
git log --oneline   # 查看简洁的提交历史
git diff            # 查看未暂存的修改内容
# ── 撤销操作  ──────────────────────────────────
git checkout -- filename.py   # 撤销⼯作区的修改（危险！不可恢复）
git reset HEAD filename.py    # 将⽂件从暂存区移出（不删除修改）
git reset --soft HEAD~1       # 撤销上⼀次  commit （保留修改在暂存区）
# ── 远程操作  ──────────────────────────────────
git remote -v                 # 查看远程仓库地址
git fetch origin              # 下载远程更新（但不合并）
git merge origin/main         # 合并远程分⽀到当前分⽀
⚠  git reset --hard 会永久丢弃修改，操作前请确认！有 Git 记录才能找回历史

你的本地                           GitHub 远程
    │                                  │

任务：创建你的第⼀个 Git 仓库并推送到 GitHub

Cursor：项⽬级 AI 编程
上⼀讲我们学了 Cursor 的基础快捷键，这⾥重点看项⽬级功能：
Ctrl+Enter ：扫描整个项⽬
普通  AI 问答（ Ctrl+L ）：
  " 这个函数怎么优化？ "  → AI 只看当前⽂件的上下⽂
项⽬级  AI （ Ctrl+Enter ）：
  " 这个项⽬的数据库连接逻辑在哪⾥？ "
  → AI 扫描所有⽂件，找到  application.yml + DataSource 配置
  → 给出跨⽂件的分析答案
实践场景：拿到⼀个陌⽣开源项⽬
1. ⽤ git clone 下载到本地，⽤ Cursor 打开
2. Ctrl+Enter ：问"这个项⽬的整体架构是什么？⼊⼝在哪⾥？"
3. AI 帮你⽣成项⽬导览，⽐⾃⼰读代码快 10 倍

Vercel：从 GitHub 到线上的 3 步
Vercel 是专为前端和全栈项⽬设计的零配置部署平台
步骤  1 ：连接  GitHub
  登录  vercel.com → 点击  "New Project" → 授权  GitHub
步骤  2 ：导⼊仓库
  选择你的仓库  → 选择框架（ Next.js / Vue / React / 静态⽹站）
  → Vercel ⾃动检测构建命令
步骤  3 ：部署完成
  点击  Deploy → 约  1-2 分钟  → ⾃动获得  https://your-project.vercel.app
特性 说明
⾃动触发 每次 git push  到 main，⾃动重新部署
预览部署 每个 Pull Request ⾃动⽣成独⽴预览链接
⾃定义域名免费⽀持绑定⾃⼰的域名（加 CNAME 记录）
免费额度 个⼈项⽬完全免费

课堂总结：⼯具链如何防⽌ Knight Capital 式灾难
Knight Capital 的问题 现代⼯具链的解决⽅案
旧代码⽆⼈知晓存在哪⾥git log  完整追踪每个⽂件的每次变更
