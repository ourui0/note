# 期末复习

## 排序相关

### **一、必然成立的结论（普适性质）**

1. **逆序对数量单调递减**

   任何基于**元素比较**的排序算法，每次有效操作（如交换相邻元素）至多消除一个逆序对。

   - **原因**：若某操作可消除多个逆序对，则算法时间复杂度可能低于Ω(n²)，但比较排序的下界为Ω(n log n)，矛盾。

2. **比较排序的时间复杂度下界**

   - 任何基于比较的排序算法，最坏时间复杂度至少为 **Ω(n log n)**。

     **证明**：决策树模型有n!个叶子节点（对应所有排列），树高至少为log₂(n!)=Ω(n log n)。

3. **输出有序性**

   任何正确的排序算法输出必须满足**单调性**（升序/降序），且是输入序列的一个排列。

4. **非比较排序可突破下界**

   非比较排序（如桶排序、基数排序）在特定条件下（如数据均匀分布）可达到 **O(n)** 时间复杂度，但需满足额外约束（如数据范围有限）。

------

### **二、仅对特定算法成立的结论**

#### **1. 稳定性**

- **成立算法**：插入排序、归并排序、桶排序（取决于桶内排序方式）。

  **原因**：保留相等元素的原始相对位置（如插入排序不跨越交换相等元素）。

- **不成立算法**：堆排序、快速排序（分区时可能交换相等元素）。

  **反例**：序列 `[2a, 2b, 1]`经堆排序后可能输出 `[1, 2b, 2a]`（破坏相等元素顺序）。

#### **2. 逆序对消除效率**

- **冒泡排序**：每次交换**恰好消除1个**逆序对，总交换次数 = 初始逆序对数量。
- **插入排序**：逆序对减少量 = 元素移动次数，平均为O(n²)。
- **归并排序**：合并时可消除多个逆序对（跨子数组比较），时间复杂度O(n log n)。

#### **3. 输入敏感性**

- **插入排序**：对近乎有序的输入效率高（时间复杂度 **O(n)**）。
- **快速排序**：最坏情况 **O(n²)**（如输入已有序），但随机化版本期望O(n log n)。
- **桶排序**：仅当数据均匀分布时达到 **O(n)**，否则退化为O(n log n)或更差。

#### **4. 空间复杂度**

- **原地排序**：堆排序、快速排序（额外空间 **O(1)**）。
- **非原地排序**：归并排序（额外空间 **O(n)**）。

------

### **三、易混淆结论辨析**

| **结论**                      | **是否普适** | **反例/说明**                    |
| ----------------------------- | ------------ | -------------------------------- |
| **交换相邻元素至多消1逆序对** | 是           | 所有比较排序均遵守               |
| **算法稳定性**                | 否           | 堆排序不稳定（子树调整破坏顺序） |
| **时间复杂度O(n)**            | 否           | 仅非比较排序在特定条件下成立     |
| **最坏时间复杂度O(n log n)**  | 否           | 快速排序最坏O(n²)                |

------

### **四、总结**

- **必然成立**的性质多与问题本质相关（如逆序对变化、复杂度下界）。

- **算法特定**的性质取决于设计策略（如是否稳定、空间开销）。

  复习时需结合具体算法流程分析性质，例如：

  - 为何归并排序稳定而快速排序不稳定？

    → 归并排序合并时不改变相等元素顺序；快速排序分区时可能交换相等元素。

  - 为何桶排序可突破Ω(n log n)下界？

    → 桶排序是非比较排序，利用数据分布特性直接分桶，无需比较。

### **五、逆序对的定义**

#### **1. 基本定义**

- **逆序对（Inversion Pair）**：

  在序列 a1,a2,…,an中，若存在下标 i<j且 ai>aj，则称 (ai,aj)构成一个逆序对。

  **示例**：序列 `[3, 1, 2]`的逆序对为 (3,1)和 (3,2)（共2对）。

#### **2. 核心意义**

- **衡量序列有序度**：

  逆序对数量越多，序列越无序；数量为0时序列完全升序。

- **排序算法的关键指标**：

  许多排序算法的核心操作是消除逆序对（如交换相邻元素）。

## 二叉树

### **一、遍历序列与二叉树结构的对应关系**

#### **1. 核心约束机制**

- **前序遍历（Preorder）**：根节点 → 左子树 → 右子树
- **中序遍历（Inorder）**：左子树 → 根节点 → 右子树
- **后序遍历（Postorder）**：左子树 → 右子树 → 根节点

#### **2. 唯一确定二叉树的条件**

| **序列组合**    | **能否唯一确定结构** | **原因与示例**                                               |
| --------------- | -------------------- | ------------------------------------------------------------ |
| **前序 + 中序** | ✅ 是                 | 前序定位根节点，中序划分左右子树（递归重建）。 **示例**：前序 `[3,9,20,15,7]`+ 中序 `[9,3,15,20,7]`→ 唯一二叉树。 |
| **后序 + 中序** | ✅ 是                 | 后序定位根节点，中序划分左右子树（递归重建）。               |
| **前序 + 后序** | ❌ 否                 | 无法区分左右子树边界（子树为空时歧义）。 **示例**：前序 `[1,2]`+ 后序 `[2,1]`→ 可能为左斜树或右斜树。 |

#### **3. 歧义场景分析**

- **前序+后序的歧义根源**：

  后序序列的根节点在末尾，但无法确定左右子树分界。例如：

  - 前序 `[A,B]`+ 后序 `[B,A]`对应两种结构：
    1. A 为根，B 为左子树（左斜树）。
    2. A 为根，B 为右子树（右斜树）。

------

### **二、二叉树结构计数的建模思路**

#### **1. 递归分解法（Catalan数模型）**

- **核心思想**：将问题分解为左子树和右子树的子问题。

  - 对于 n个节点的二叉树，固定根节点后：

    - 左子树有 k个节点，右子树有 n−1−k个节点（0≤k≤n−1）。

    - 结构数量递推公式：

      ```
      Cn=k=0∑n−1Ck⋅Cn−1−k
      ```

      其中 C0=1（空树），C1=1（单节点）。

- **Catalan数性质**：

  - Cn=n+11(n2n)，表示 n个节点的不同二叉树形态数。
  - **示例**：3 个节点时 C3=5，对应 5 种不同结构。

#### **2. 组合计数法**

- **关键点**：利用二叉树与栈操作序列的等价性（如入栈序列对应中序，出栈序列对应前序）。
  - **栈序列约束**：合法的入栈/出栈序列数量为 Catalan 数 Cn，二叉树结构一一对应。
- **应用场景**：
  - 计算给定节点数的二叉树形态总数（如考题要求计算 n=4时的可能结构数）。

------

### **三、总结**

1. **遍历序列与结构关系**：

   - **唯一确定性**依赖中序序列提供左右子树划分信息。
   - 前序/后序组合因缺失子树边界信息导致歧义。

2. **结构计数建模**：

   - **递归分解**：通过左/右子树规模递推（Catalan 数模型）。

   - **组合映射**：利用栈序列与二叉树的等价性直接计数。

     **复习重点**：掌握前序+中序重建二叉树的递归模拟，以及 Catalan 数在结构计数中的推导逻辑。

## 一般树相关

### **一、树的全局性质如何由子树信息汇总**

#### **1. 子树信息聚合机制**

- **子树大小（size）**：

  以节点 `r`为根的树大小 = 1 + ∑（所有子树的大小）。

  示例：计算子树大小时需递归遍历所有子节点并累加。

- **深度（depth）**：

  节点深度 = 父节点深度 + 1；树的高度 = max（所有子树高度）+ 1。

- **平衡性（balance）**：

  平衡二叉树（如AVL树）的平衡因子 = 左子树高度 - 右子树高度。

  全局平衡需满足：所有节点的平衡因子 ∈ [-1, 1]，且递归检查每棵子树。

#### **2. 汇总原理**

- **分治思想**：全局性质（如size/depth）通过递归分解为子树性质，再逐层向上合并。
- **动态维护**：修改子树后需更新路径上的祖先节点信息（如高度、平衡因子）。

------

### **二、树结构修改后的影响**

#### **1. 局部变化传播到整体**

- **搜索树调整（如BST/红黑树）**：

  - **插入/删除节点**：可能破坏BST性质（左<根<右）或红黑树约束（如颜色、黑高）。
  - **修复操作**：通过旋转（左旋/右旋）和变色局部调整，但需递归向上检查祖先节点是否违反全局性质。

- **示例**：

  红黑树插入后若违反“无红边”约束，需依次处理父节点和祖父节点，直至根节点（可能需变色）。

#### **2. 影响范围**

- **时间复杂度**：修复操作的传播路径最长可达树高，故平衡树（如红黑树）为 *O*(log *n*)，非平衡树最坏 *O*(*n*)。
- **空间复杂度**：递归调整依赖栈空间，最坏 *O*(*n*)。

------

### **三、需要掌握的核心能力**

#### **1. DFS在树中的应用**

- **计算全局信息**：

  通过DFS遍历（前序/中序/后序）递归计算子树性质（如size、深度、路径和）。

  示例：后序遍历中先计算子树高度，再更新当前节点高度。

- **复杂问题**：

  如Tarjan算法用DFS计算强连通分量（SCC），依赖子树信息（`dfn`/`low`）。

#### **2. 树问题转换为子树问题**

- **递归分解**：

  将问题拆解为独立子树子问题（如二叉树重建需中序+前序/后序序列划分左右子树）。

- **组合计数**：

  *n*个节点的二叉树形态数 = Catalan数 *Cₙ*= ∑（左子树形态数 × 右子树形态数）。

#### **3. 搜索树的原理与性质**

- **BST性质**：

  左子树所有节点 < 根 < 右子树所有节点。中序遍历序列严格升序。

- **平衡搜索树**：

  - **红黑树**：通过颜色约束（根黑、无红边、黑高一致）和旋转，保证树高 *O*(log *n*)。
  - **Treap**：结合BST与堆性质，随机优先级避免退化。

- **操作复杂度**：

  搜索、插入、删除均可在 *O*(log *n*) 完成（平衡树下）。

------

### **总结**

- **全局性质**：依赖子树信息的递归汇总（如DFS后序遍历）。
- **结构修改**：局部调整可能传播至根节点，需动态维护性质（如红黑树的旋转/变色）。
- **关键技能**：
  - 用DFS计算子树信息并聚合；
  - 将问题分解为子树子问题（如Catalan数模型）；
  - 掌握搜索树的约束与平衡机制（BST性质、红黑树规则）。

## 堆

### **一、堆中元素的位置关系与约束**

#### **1. 堆的性质**

- **堆的定义**：完全二叉树，满足堆性质：
  - **最大堆**：每个节点（除根节点）的值 ≤ 其父节点的值。
  - **最小堆**：每个节点（除根节点）的值 ≥ 其父节点的值。
- **位置关系**：
  - 根节点（索引 1）是最大值（最大堆）或最小值（最小堆）。
  - 任意节点 `i`的父节点索引为 `i//2`，左子节点为 `2*i`，右子节点为 `2*i+1`（数组存储）。

#### **2. 必然成立的结论**

- **堆顶极值性**：根节点始终是全局最大/最小值。
- **局部有序性**：子树仍满足堆性质（递归定义）。
- **完全二叉树结构**：所有层除最后一层外完全填充，最后一层节点靠左排列。

------

### **二、堆操作后的结构变化**

#### **1. 插入元素（HeapInsert）**

- **步骤**：
  1. 新元素放入数组末尾。
  2. **向上调整**：比较新元素与父节点，若违反堆性质则交换，递归至根节点。
- **结构变化**：
  - 新元素从叶子节点开始“上浮”，路径上的节点可能下移。
  - **示例**：在最大堆 `[16,14,10,8,7,9,3,2,4]`中插入 `15`：
    - 插入后：`[16,14,10,8,7,9,3,2,4,15]`
    - `15`与父节点 `7`（索引 5）比较 → 交换 → `[16,14,10,8,15,9,3,2,4,7]`
    - `15`再与父节点 `14`（索引 2）比较 → 交换 → `[16,15,10,8,14,9,3,2,4,7]`

#### **2. 删除堆顶元素（HeapExtractMax）**

- **步骤**:
  1. 移除根节点（堆顶元素）。
  2. 将末尾元素移至根节点。
  3. **向下调整（MaxHeapify）**：比较新根与子节点，若违反堆性质则与较大子节点交换，递归至叶子。
- **结构变化**：
  - 末尾元素移至根节点后“下沉”，路径上的节点可能上移。
  - **示例**：从最大堆 `[16,14,10,8,7,9,3,2,4]`删除根节点：
    - 移走 `16`，末尾 `4`移至根 → `[4,14,10,8,7,9,3,2]`
    - `4`与子节点 `14`、`10`比较 → 与 `14`交换 → `[14,4,10,8,7,9,3,2]`
    - `4`再与子节点 `8`、`7`比较 → 与 `8`交换 → `[14,8,10,4,7,9,3,2]`

------

### **三、需要掌握的操作及原理**

#### **1. 核心操作**

- **HeapInsert**：插入元素，时间复杂度 *O*(log *n*)。
- **HeapExtractMax/Min**：删除堆顶元素，时间复杂度 *O*(log *n*)。
- **GetMax/Min**：返回堆顶元素，时间复杂度 *O*(1)。
- **BuildMaxHeap**：将无序数组构建为堆，时间复杂度 *O*(*n*)（自底向上调整）。

#### **2. 操作原理**

- **向上调整**：插入后从新节点向根节点方向比较交换。
- **向下调整**：删除堆顶后从根节点向叶子方向比较交换（需递归比较子节点）。
- **建堆优化**：从最后一个非叶子节点（索引 `n//2`）开始向前遍历并向下调整。

------

### **四、堆的具体实现**

#### **1. 数组存储**

- 堆使用数组存储，索引从 1 开始（部分实现从 0 开始）。
- 节点关系：`parent(i) = i//2`, `left(i) = 2*i`, `right(i) = 2*i+1`。

#### **2. 关键函数伪代码**

- **MaxHeapify（向下调整）**：

  ```python
  def MaxHeapify(i, A):
      left = 2*i, right = 2*i+1
      max_idx = i
      if left ≤ heap_size and A[left] > A[max_idx]:
          max_idx = left
      if right ≤ heap_size and A[right] > A[max_idx]:
          max_idx = right
      if max_idx ≠ i:
          swap(A[i], A[max_idx])
          MaxHeapify(max_idx, A)
  ```

- **HeapInsert（向上调整）**：

  ```python
  def HeapInsert(A, key):
      heap_size += 1
      A[heap_size] = key
      i = heap_size
      while i > 1 and A[i] > A[i//2]:
          swap(A[i], A[i//2])
          i = i//2
  ```

------

### **五、应用场景**

1. **优先队列**：
   - `HeapInsert`对应入队，`HeapExtractMax`对应出队。
   - 用于任务调度、事件模拟等场景。
2. **堆排序（HeapSort）**：
   - 步骤：
     1. `BuildMaxHeap`构建最大堆。
     2. 重复 `HeapExtractMax`并将最大值放入数组末尾。
   - 时间复杂度：*O*(*n*log *n*)，空间复杂度 *O*(1)。

------

### **总结**

- **复习重点**：
  1. **位置关系**：完全二叉树结构 + 父子节点大小约束。
  2. **操作变化**：插入时元素“上浮”，删除时元素“下沉”。
  3. **实现核心**：数组存储 + 向上/向下调整函数。
- **典型考题**：
  - 给定操作序列，画出堆的中间状态（如插入 `15`后的堆结构）。
  - 分析堆排序每一步的数组变化。

## 并查集

### **一、维护策略与优化思想**

#### **1. 路径压缩（Path Compression）**

- **原理**：在 `Find(x)`操作中，当从节点 `x`向上遍历到根节点时，**让路径上的所有节点直接指向根节点**，从而扁平化树结构。

- **影响**：

  - **减少后续 `Find`操作的路径长度**：压缩后树高降低，后续查询更快。
  - **时间复杂度优化**：均摊时间复杂度从 *O*(log *n*) 降至接近 *O*(α(*n*))（α(*n*) 为反阿克曼函数，增长极慢）。

- **示例**：

  初始路径 `x → y → z → root`，压缩后变为 `x → root`、`y → root`、`z → root`。

#### **2. 按秩合并（Union-by-Rank）**

- **原理**：维护每个根的**秩（rank）**（树高的上界）。`Union(x, y)`时：
  - 若 `rank[rootX] < rank[rootY]`，将 `rootX`合并到 `rootY`下。
  - 若 `rank[rootX] > rank[rootY]`，将 `rootY`合并到 `rootX`下。
  - 若秩相等，合并后**增加新根的秩**（如 `rank[rootX] += 1`）。
- **影响**：
  - **控制树高增长**：秩较小的树合并到秩较大的树下，避免树高线性增长。
  - **避免退化**：最坏树高为 *O*(log *n*)，与路径压缩结合后优化至 *O*(α(*n*))。

#### **3. 操作序列的影响**

- **`Find`/`Union`交错时的变化**：
  - **`Union`依赖 `Find`**：`Union(x, y)`需先 `Find(x)`和 `Find(y)`获取根节点。
  - **路径压缩的连锁效应**：一次 `Find`压缩路径后，后续 `Union`和 `Find`的树结构更扁平。
- **推导方法**：
  - 模拟操作序列（如 `MakeSet`→ `Union`→ `Find`），跟踪秩和父指针变化。
  - **示例序列**：
    - `MakeSet(a), MakeSet(b), Union(a, b)`：树高为 1。
    - `Find(a)`：若路径压缩，`a`直接指向根。
    - 后续 `Union(c, a)`：`c`合并到 `a`的根下，秩可能增加。

------

### **二、需要掌握的核心内容**

#### **1. 路径压缩的原理及实现**

- **原理**：通过递归或迭代将路径节点直接链接到根节点，减少树高。

- **实现伪代码**：

  ```python
  def Find(x):
      if parent[x] != x:          # 若非根节点
          parent[x] = Find(parent[x])  # 递归压缩路径
      return parent[x]             # 返回根节点
  ```

- **时间复杂度**：单次 `Find`最坏 *O*(log *n*)，均摊 *O*(α(*n*))。

#### **2. 按秩合并的原理及实现**

- **原理**：秩表示树高的上界，合并时优先保留高秩树以控制高度。

- **实现伪代码**：

  ```python
  def Union(x, y):
      rootX = Find(x)              # 获取 x 的根
      rootY = Find(y)              # 获取 y 的根
      if rootX == rootY:           # 已在同一集合
          return
      if rank[rootX] < rank[rootY]:
          parent[rootX] = rootY    # 低秩树合并到高秩树
      elif rank[rootX] > rank[rootY]:
          parent[rootY] = rootX
      else:                        # 秩相等时
          parent[rootY] = rootX
          rank[rootX] += 1         # 新根秩增加
  ```

- **关键点**：秩仅在合并秩相等的树时增加，确保树高增长缓慢。

------

### **三、总结**

- **优化协同效应**：路径压缩与按秩结合，使 `Find`和 `Union`的均摊时间复杂度接近 *O*(1)。
- **操作序列分析**：
  - `Union`改变树结构，`Find`压缩路径，两者交错时需动态维护秩和父指针。
  - 例如，频繁 `Find`后树高降低，后续 `Union`可能更快。
- **复习重点**：
  1. 掌握路径压缩的递归实现（更新父指针至根）。
  2. 理解按秩合并的规则（秩比较与递增条件）。
  3. 通过模拟操作序列（如 `MakeSet`→ `Union`→ `Find`）推导结构变化。

## 哈希函数

### **一、性能与边界情况**

#### **1. 冲突（Collision）**

- **定义**：不同键（Key）通过哈希函数映射到同一桶（Bucket）位置。
- **影响**：
  - 冲突率过高导致查询/插入效率退化（从 *O*(1) 退化为 *O*(*n*)）。
  - **边界案例**：所有键哈希到同一桶 → 退化为链表（链地址法）或线性探测失效（开放寻址法）。

#### **2. 退化情形**

- **哈希函数设计缺陷**：
  - 键分布不均匀 → 部分桶过载（如 `hash(key) = key % 100`，但所有键均为 `100`的倍数）。
- **恶意攻击**：
  - 攻击者构造大量哈希冲突的键（如 HashDoS 攻击），使操作退化为 *O*(*n*)。
- **负载因子过高**：
  - 默认阈值（如 Java HashMap 的 `0.75`），超过时触发扩容（Rehash）。

------

### **二、实现细节**

#### **1. 查找（Search）**

- **步骤**：
  1. 计算哈希值 `h = hash(key)`。
  2. 定位桶 `bucket = h % table_size`。
  3. **冲突处理**：
     - **链地址法**：遍历桶内链表/树查找键。
     - **开放寻址法**：按探测序列（线性/二次探测）查找下一个空桶。

#### **2. 插入（Insert）**

- **步骤**：
  1. 若键已存在，更新值（或报错）。
  2. 若桶为空，直接插入。
  3. **冲突处理**：
     - **链地址法**：新键加入链表/树。
     - **开放寻址法**：按探测序列找到空桶插入。
  4. **检查负载因子**：若超过阈值，触发 Rehash。

#### **3. Rehash 的触发与代价**

- **触发条件**：负载因子（元素数/桶数）超过阈值（通常 `0.7~0.75`）。
- **Rehash 过程**：
  1. 创建新桶数组（大小为原数组的 `2`倍）。
  2. 遍历原表所有键值对，重新哈希到新桶。
- **代价**：
  - 时间复杂度：*O*(*n*)（需迁移所有元素）。
  - **优化策略**：渐进式 Rehash（如 Redis 分步迁移，避免单次阻塞）。

------

### **三、需要掌握的核心内容**

#### **1. 哈希表类型与操作流程**

| **类型**       | **冲突解决**    | **操作流程**                                                 |
| -------------- | --------------- | ------------------------------------------------------------ |
| **链地址法**   | 桶内链表/红黑树 | 插入：哈希后追加链表（或树插入）；查找：遍历链表（或树搜索） |
| **开放寻址法** | 线性/二次探测   | 插入：按探测序列找空桶；查找：按探测序列比较键，遇空桶终止   |
| **布谷鸟哈希** | 双哈希函数+踢出 | 插入：若桶被占，踢出原元素并重新哈希插入；查找：检查两个桶位置 |

#### **2. 各类哈希表的原理**

- **链地址法（Separate Chaining）**：
  - 桶内维护链表（或平衡树），冲突元素追加到链表。
  - **优点**：简单，抗退化（链表过长可转红黑树）。
  - **缺点**：额外指针开销（空间 *O*(*n*+ *m*)）。
- **开放寻址法（Open Addressing）**：
  - 所有元素存于桶数组，冲突时按探测序列（如 `h(k,i) = (hash1(k) + i) % size`）找空桶。
  - **优点**：无指针开销，缓存友好。
  - **缺点**：负载因子需更低（通常 `≤0.7`），否则效率骤降。
- **布谷鸟哈希（Cuckoo Hashing）**：
  - 使用两个哈希函数 `h1(k)`、`h2(k)`，每个键有两个候选桶。
  - 插入时若桶被占，踢出原元素并重新哈希插入该元素（递归至空桶或最大迭代次数）。
  - **优点**：最坏查询时间 *O*(1)。
  - **缺点**：插入可能失败（需扩容或重哈希）。

------

### **四、关键考点总结**

1. **冲突处理机制对比**：
   - 链地址法适合高负载场景，开放寻址法空间利用率高但易退化。
2. **Rehash 的必要性**：
   - 负载因子过高导致冲突率指数增长，必须扩容。
3. **时间复杂度边界**：
   - 理想 *O*(1)，但最坏情况（全冲突）退化为 *O*(*n*)。
4. **设计权衡**：
   - 哈希函数应均匀分布（如 MurmurHash），桶大小取质数减少聚集。

------

### **五、典型问题示例**

- **问题**：哈希表大小为 `7`，哈希函数 `h(k) = k % 7`，使用线性探测（`h(k,i) = (k % 7 + i) % 7`）。插入序列 `[3, 10, 17, 24]`后，桶数组状态如何？

  **答案**：

  - `3 % 7 = 3`→ 桶 `3`

  - `10 % 7 = 3`（冲突）→ 探测桶 `(3+1)%7=4`

  - `17 % 7 = 3`（冲突）→ 探测桶 `(3+1)%7=4`（冲突）→ `(3+2)%7=5`

  - `24 % 7 = 3`（冲突）→ 探测桶 `4`（冲突）→ `5`（冲突）→ `6`

    → 桶数组：`[_, _, _, 3, 10, 17, 24]`

------

1. 掌握冲突处理机制（链地址法 vs. 开放寻址法）的实现差异。
2. 理解 Rehash 的触发条件与代价（尤其渐进式迁移）。
3. 通过模拟操作序列分析哈希表状态变化（如插入/删除后的桶分布）。

## 图的概念与图的遍历

### **一、遍历过程中的结构信息刻画**

#### **1. DFS遍历的边分类与状态演化**

- **边类型**（依据DFS森林）：
  - **树边（Tree Edge）**：DFS森林中的边，节点`v`为白色时被探索。
  - **后向边（Back Edge）**：指向祖先节点的边（`v`为灰色）。
  - **前向边（Forward Edge）**：指向后代节点的非树边（`v`为黑色）。
  - **交叉边（Cross Edge）**：无祖先-后代关系的边（`v`为黑色）。
- **状态标记**：
  - **白色（WHITE）**：未发现。
  - **灰色（GRAY）**：已发现未完成（递归中）。
  - **黑色（BLACK）**：已完成处理。
- **活跃区间**：
  - 发现时间（`u.d`）与完成时间（`u.f`）满足括号定理：任意两节点区间要么不相交，要么完全包含。

#### **2. BFS遍历的层级关系**

- **分层遍历**：从源点`s`开始，按距离分层访问节点（距离`d=0,1,2,...`）。
- **最短路径**：BFS树中`s`到`u`的路径是最短路径。
- **状态维护**：
  - 未发现（WHITE）、已发现（GRAY，在队列中）、已访问（BLACK，出队）。

### **二、基础概念的判定与推理**

#### **1. 连通性判定**

- **无向图**：通过DFS/BFS遍历，若所有节点被访问则连通；否则有多个连通分量。
- **有向图**：强连通分量（SCC）需借助DFS两次遍历（原图与转置图）。

#### **2. 环的检测**

- **无向图**：DFS中若存在后向边，则存在环。
- **有向图**：DFS中若存在后向边，则存在环；拓扑排序失败也表明有环。

#### **3. 拓扑排序**

- **条件**：有向无环图（DAG）必有拓扑序。
- **方法**：DFS完成后按`u.f`降序排列。

### **三、需要掌握的核心内容**

#### **1. DFS与BFS的原理**

- **DFS**：递归/栈实现，优先深度探索，生成DFS森林。
- **BFS**：队列实现，按层探索，生成最短路径树。

#### **2. 遍历时边的性质**

- **DFS边性质**：
  - 无向图中仅有树边和后向边。
  - 白路径定理：`v`是`u`的后代 iff `u`发现时存在`u→v`的全白路径。
- **BFS边性质**：所有边连接同层或相邻层节点。

#### **3. 图的核心概念**

- **连通性**：无向图的连通分量、有向图的强连通分量。
- **图结构**：DFS/BFS树、活跃区间、时间戳。
- **应用场景**：
  - 拓扑排序（任务调度）。
  - SCC计算（编译器依赖分析）。
  - 最短路径（无权图BFS）。

### **总结**

- **遍历刻画**：DFS/BFS的状态转换（颜色标记）和边分类（树边、后向边等）是理解图结构的关键。
- **概念判定**：连通性、环、拓扑序可通过遍历过程中的边性质动态判断。
- **核心掌握**：DFS/BFS的遍历逻辑、时间复杂度（均为*O*(*n*+*m*)）及边分类规则。

## 有向无环图和拓扑排序

### **一、DAG的结构特征与判定规则**

#### **1. 核心定义**

- **DAG（Directed Acyclic Graph）**：有向图且**无环**（即不存在任何路径使得节点能回到自身）。

- **关键性质**：
  - **拓扑序存在性**：DAG必有拓扑排序（线性序列满足所有边方向一致）。

  - **边类型约束**：DFS遍历中**无后向边**（Back Edge）。

#### **2. 判定规则**

- **DFS判定法**：

  执行DFS遍历，若存在**后向边**（指向祖先节点的边），则图有环；否则为DAG。

  - **证明**：
    - 若存在环 → DFS中必有后向边（环中最早发现的节点有路径指向其后发现的节点）。

    - 若无后向边 → 图无环（所有边为树边、前向边或交叉边）。

- **度数判定法**：

  DAG中至少存在一个**源节点**（入度=0）和一个**汇节点**（出度=0）。

------

### **二、拓扑序的约束分析**

#### **1. 唯一性条件**

- **唯一拓扑序**：当且仅当DAG是**全序关系**（任意两节点间存在路径），否则存在多个拓扑序。
  - **示例**：序列 `[A,B,C]`的两种拓扑序：
    - `A→B→C`（若边 `A→B`, `B→C`）。

    - `A→C→B`（若边 `A→C`, `C→B`，且 `B`与 `C`无直接路径）。

#### **2. 相邻约束**

- **相邻节点顺序**：若存在边 `(u,v)`，则 `u`必在 `v`前。
  - **反例**：序列 `[B,D,C,A]`中若存在边 `A→B`，则非法（`A`必须在 `B`前）。

#### **3. 可行性条件**

- **可行拓扑序存在**：当且仅当图为DAG（无环）。
  - **反例**：序列 `[B,D,C,A]`若存在环（如 `B→D→C→B`），则无拓扑序。

------

### **三、拓扑排序的实现原理**

#### **1. 基于DFS的算法**

- **步骤**：

  1. 对图执行DFS，记录节点**完成时间**（`u.f`）。
  2. 按 `u.f`**降序**排列节点，即为拓扑序。

- **原理**：

  DAG中任意边 `(u,v)`满足 `u.f > v.f`（`u`先完成，`v`后完成）。

- **时间复杂度**：O(n+m)（n为节点数，m为边数）。

#### **2. Kahn算法（基于入度）**

- **步骤**：

  1. 统计所有节点入度，将入度为0的节点加入队列。
  2. 取出队首节点 `u`，输出 `u`，删除 `u`的所有出边（邻居入度减1）。
  3. 若邻居入度降为0，则入队。
  4. 重复直至队列为空。若输出节点数 <总节点数，则图有环。

- **原理**：

  不断移除源节点（入度=0），打破局部依赖链。

- **时间复杂度**：O(n+m)。

------

### **四、关键结论总结**

| **主题**            | **结论**                      | **依据** |
| ------------------- | ----------------------------- | -------- |
| **DAG判定**         | 无后向边 ⇔ DAG                |          |
| **拓扑序存在性**    | DAG ⇔ 存在拓扑序              |          |
| **拓扑序唯一性**    | 任意两节点有路径 ⇔ 唯一拓扑序 |          |
| **DFS拓扑排序原理** | 按完成时间降序排列            |          |
| **Kahn算法适用性**  | 需动态维护入度，适合动态图    |          |

**复习重点**：

- 掌握DFS和Kahn算法的流程及原理。
- 理解拓扑序约束（如相邻节点顺序、唯一性条件）。
- 通过模拟操作验证DAG判定（如DFS边分类）和拓扑序生成。

## （强）连通分量和tarjan算法

### 一、强连通分量（SCC）的定义与性质

1. **定义**：
   - **强连通**：有向图中节点u和v互达（存在u→v和v→u路径）。
   - **SCC**：极大强连通子图（任意两节点互达，且无法添加更多节点）。
2. **关键性质**：
   - **缩点图**：将SCC视为单个节点后，形成有向无环图（DAG）。
   - **传递性**：若u→v和v→w，则u和w在同一SCC中（互达性传递）。
   - **唯一分解**：有向图可唯一分解为若干互不相交的SCC。

### 二、互达结构的抽象与分解

#### 1. **强连通判定**

- **充要条件**：节点u和v属于同一SCC当且仅当：
  1. 存在u→v路径
  2. 存在v→u路径
- **判定方法**：
  - **DFS双向验证**：从u出发DFS可达v，且从v出发DFS可达u。
  - **Tarjan算法**：通过单次DFS同时识别所有SCC（见下文）。

#### 2. **分块思想**

- **缩点（Condensation）**：
  - 将每个SCC抽象为一个超级节点。
  - 超级节点间保留原图边（去除SCC内部边）。
- **结果**：缩点图必为DAG，便于拓扑排序和依赖分析。

### 三、栈与时间戳在Tarjan算法中的作用

#### 1. **时间戳（dfn与low）**

- **dfn[u]**：节点u的DFS发现时间（唯一序号）。
- **low[u]**：u通过后向边能回溯到的最早祖先的dfn值。
- **更新规则**：
  - 初始：`low[u] = dfn[u]`
  - 对邻居v：
    - 若v未访问（树边）：递归后`low[u] = min(low[u], low[v])`
    - 若v在栈中（后向边）：`low[u] = min(low[u], dfn[v])`

#### 2. **栈的核心作用**

- **存储当前路径**：栈记录DFS递归路径上的节点。
- **SCC弹出条件**：当`dfn[u] == low[u]`时，栈中从u到栈顶的节点构成一个SCC。
- **动态维护**：节点完成访问时弹出，确保SCC分离。

### 四、Tarjan算法流程

```python
Tarjan(G):
    time = 0, stack = []
    for each node u:
        u.dfn = u.low = -1  # 未访问
    for each node u:
        if u.dfn == -1:
            DFS(u)

DFS(u):
    u.dfn = u.low = time++
    stack.push(u)
    for each neighbor v of u:
        if v.dfn == -1:     # 树边
            DFS(v)
            u.low = min(u.low, v.low)
        elif v in stack:     # 后向边
            u.low = min(u.low, v.dfn)
    
    if u.dfn == u.low:      # SCC根节点
        scc = []
        while True:
            v = stack.pop()
            scc.add(v)
            if v == u: break
        output scc
```

### 五、关键结论

| **概念**             | **结论**                            |
| -------------------- | ----------------------------------- |
| **SCC存在性**        | 有向图必有SCC分解，缩点图为DAG      |
| **Tarjan时间复杂度** | O(n+m)（每个节点和边访问一次）      |
| **栈的必要性**       | 区分后向边与交叉边，确保SCC正确弹出 |
| **low[u]的意义**     | 标识SCC的“根”（当dfn[u]=low[u]时）  |

**复习重点**：

1. 理解SCC的互达性和极大性。
2. 掌握Tarjan算法中dfn/low的更新逻辑及栈的弹出机制。
3. 通过缩点图理解DAG转化（如拓扑排序在SCC上的应用）。

## 最小生成树

### 一、最小生成树（MST）的性质与边的判定

#### 1. **最小生成树定义**

- **最小生成树（MST）**：连通无向加权图 G=(V,E)的生成树中，总权重最小的树。
- **核心性质**：MST 的任意子树也是对应子图的最小生成树（最优子结构）。

#### 2. **必选边与可替换边的判定（割性质）**

- **割（Cut）**：将节点集 V划分为两部分 S和 V−S。
- **割性质（Cut Property）**：
  - 若边集 A是某 MST 的子集，且割 (S,V−S)**尊重** A（即 A中无边跨越该割），则跨越此割的**最小权重边（轻边）** 是 A的安全边（即属于某 MST）。
- **必选边**：若一条边是某割的唯一轻边，则它必属于所有 MST。
- **可替换边**：若多条边同为某割的轻边（权重相同），则它们可互相替换（导致 MST 不唯一）。

### 二、Kruskal 与 Prim 算法的选择依据

#### 1. **算法共性**

- 均基于**贪心策略**：通过局部最优选择（轻边）逐步构建全局 MST。
- 均依赖**割性质**：每次选择安全边加入当前边集 A。

#### 2. **Kruskal 算法**

- **选择依据**：选连接不同连通分量（CC）的最小权重边。
- **全局逻辑链**：
  - 初始 A=∅，每个节点独立为连通分量。
  - 按权重升序遍历边，若边连接两个不同分量，则加入 A并合并分量。
  - **正确性**：每次选择跨越分量间割的轻边，符合割性质。

#### 3. **Prim 算法**

- **选择依据**：选连接当前子树 Cx与外部节点的最小权重边。
- **全局逻辑链**：
  - 从任意节点 x出发，初始化子树 Cx={x}。
  - 迭代选择 Cx到外部的最小权重边，扩展子树。
  - **正确性**：每次选择跨越割 (Cx,V−Cx)的轻边，符合割性质。

### 三、需要掌握的核心内容

#### 1. **最小生成树的性质**

- **唯一性**：若所有边权互异，则 MST 唯一。
- **环性质**：MST 中任意边的权重是连接其两端点的最小权重（否则可替换更小边形成更小生成树）。

#### 2. **Kruskal 算法流程**

```python
KruskalMST(G, w):
    A = ∅
    将边按权重升序排序
    for each node u in V:
        MakeSet(u)  # 初始化并查集
    for each edge (u, v) in sorted order:
        if Find(u) ≠ Find(v):  # u, v 在不同连通分量
            A = A ∪ {(u, v)}
            Union(u, v)  # 合并分量
    return A
```

- **时间复杂度**：O(mlogn)（排序 O(mlogm)+ 并查集操作 O(mα(n))）。

#### 3. **Prim 算法流程**

```python
PrimMST(G, w, x):
    A = ∅
    C_x = {x}  # 初始子树
    Q = priority_queue()  # 按节点到 C_x 的距离排序
    for each node v ≠ x:
        v.dist = ∞
    x.dist = 0
    Q.insert(x)
    while Q not empty:
        u = Q.extract_min()
        if u ∉ C_x:
            A = A ∪ {(u.parent, u)}
            C_x = C_x ∪ {u}
        for each neighbor v of u:
            if w(u, v) < v.dist:  # 更新 v 到 C_x 的距离
                v.dist = w(u, v)
                v.parent = u
                Q.decrease_key(v)
    return A
```

- **时间复杂度**：O(mlogn)（优先队列操作）。

### 四、总结

| **主题**             | **核心结论**                          |
| -------------------- | ------------------------------------- |
| **割性质**           | 轻边是安全边 → 属于某 MST             |
| **必选边**           | 唯一轻边必属所有 MST                  |
| **Kruskal 选择依据** | 连接不同分量的最小权重边              |
| **Prim 选择依据**    | 连接当前子树与外部的最小权重边        |
| **全局最优逻辑链**   | 局部轻边选择 → 通过割性质保证全局 MST |

## 最短路

### **一、最短路模型与适用条件辨析**

根据检索内容，不同最短路算法的适用场景严格取决于图的结构特征（如边权正负性、是否全源计算）：

| **算法类型**       | **适用条件**                               | **限制原因**                                                 |
| ------------------ | ------------------------------------------ | ------------------------------------------------------------ |
| **Dijkstra**       | 非负权图（有向/无向）                      | 贪心策略依赖非负权保证局部最优即全局最优                     |
| **Bellman-Ford**   | 含负权但无负环的有向图                     | 动态松弛可处理负权，但负环导致路径无限短（问题无解）         |
| **SPFA**           | Bellman-Ford的队列优化，适用同Bellman-Ford | 通过队列减少冗余松弛，但负环检测需额外机制                   |
| **Floyd-Warshall** | 全源最短路（APSP），允许负权但无负环       | 动态规划递推式要求子问题无环                                 |
| **Johnson**        | 全源最短路（APSP），含负权无负环           | 先通过虚拟节点z重赋权（w^(u,v)=w(u,v)+h(u)−h(v)≥0），再调用Dijkstra |

------

### **二、算法执行过程的语义解析**

#### **1. 核心概念定义**

- **`dist`数组**：
  - **SSSP**（单源）：`dist[u]`表示从源点`s`到`u`的当前最短路径估计值。
  - **APSP**（全源）：`dist[u][v]`表示从`u`到`v`的当前最短路径估计值。
- **松弛操作（Relaxation）**：
  - 对边`(u, v)`，若`dist[v] > dist[u] + w(u, v)`，则更新`dist[v] = dist[u] + w(u, v)`。
  - **语义**：通过`u`缩短`s→v`的路径。
- **收敛条件**：
  - **Dijkstra**：优先队列为空时所有节点收敛（无负权保证）。
  - **Bellman-Ford**：完成`n-1`轮全边松弛后，若仍可更新则存在负环。

#### **2. 算法流程中的语义**

| **算法**           | **关键步骤语义**                                             |
| ------------------ | ------------------------------------------------------------ |
| **Dijkstra**       | 优先队列按`dist`贪心选取节点，松弛其邻边（非负权下保证局部最优）。 |
| **Bellman-Ford**   | 多轮全边松弛逐步逼近最短路径（第`k`轮松弛后得到最多`k`条边的最短路径）。 |
| **Floyd-Warshall** | 动态规划递推：`dist[u][v][r] = min( dist[u][v][r-1], dist[u][x_r][r-1] + dist[x_r][v][r-1] )`，其中`x_r`为中间节点。 |
| **Johnson**        | 先通过Bellman-Ford计算势函数`h(u)`，再对所有节点调用Dijkstra（重赋权后无负权）。 |

------

### **三、需要掌握的核心内容**

#### **1. 三类最短路算法流程与原理**

| **算法**           | **流程**                           | **时间复杂度** | **原理**                                                 |
| ------------------ | ---------------------------------- | -------------- | -------------------------------------------------------- |
| **Dijkstra**       | 优先队列贪心扩展 + 松弛邻边        | O((n+m)logn)   | 非负权下局部最优即全局最优                               |
| **Bellman-Ford**   | 多轮全边松弛（`n-1`轮） + 负环检测 | O(nm)          | 动态规划（最多`k`条边的最短路径）                        |
| **Floyd-Warshall** | 三重循环动态规划（中间节点迭代）   | O(n3)          | 递推式：dist[u][v]=min(dist[u][v],dist[u][x]+dist[x][v]) |

#### **2. 最短路性质与边关系**

- **三角不等式**：对任意边`(u, v)`，有dist(s,v)≤dist(s,u)+w(u,v)。

- **负环判定**：若图存在负环，则某些节点的`dist`值会无限下降（Bellman-Ford第`n`轮仍可松弛）。

- **重赋权性质**（Johnson）：

  ```
  w^(u,v)=w(u,v)+h(u)−h(v)≥0且distG(u,v)=distG^(u,v)−h(u)+h(v)
  ```

  保持最短路径结构。

------

### **四、总结**

- **模型选择**：
  - 非负权图 → Dijkstra（高效）；含负权无负环 → Bellman-Ford/SPFA；全源 → Floyd-Warshall/Johnson。
- **核心操作**：松弛是动态逼近最优解的关键，收敛条件依赖图性质（如负环检测需额外轮次）。
- **性质应用**：三角不等式用于算法正确性证明，重赋权是Johnson算法突破负权限制的核心。

2. 理解Bellman-Ford的松弛轮次与负环检测逻辑。
3. 熟练Floyd-Warshall递推式的中间节点迭代原理。

## Master定理和不适用情况

## 一、 主定理 (Master Theorem) 详解

### 1. 适用形式

对于递归式 $T(n) = a \cdot T(n/b) + f(n)$，其中 $a \ge 1, b > 1$。

通常假设 $f(n) = \Theta(n^d)$。

### 2. 复杂度分类

- Case 1：递归成本主导

  若 $a > b^d$，则 $T(n) = \Theta(n^{\log_b a})$。

- Case 2：成本平衡

  若 $a = b^d$，则 $T(n) = \Theta(n^d \log n)$。

- Case 3：合并成本主导

  若 $a < b^d$，则 $T(n) = \Theta(n^d)$。

### 3. 不适用场景（主定理的局限性）

- **非多项式差异**：当 $f(n)$ 与 $n^{\log_b a}$ 的差距小于任何多项式因子（如差一个 $\log n$）时。
- **子问题规模不规整**：如 $T(n) = T(n/3) + T(2n/3) + n$。
- **$a$ 不是常数**：如 $T(n) = n \cdot T(n/2) + n$。

------

## 二、 进阶方案：递归树法 (Recursion Tree)

*适用于子问题规模不一致的情况。以 $T(n) = T(n/3) + T(2n/3) + n$ 为例：*

### 1. 构造逻辑

- **节点拆分**：根节点代价为 $n$，向下分裂为 $n/3$ 和 $2n/3$ 两个子节点。
- **单层总代价**：
  - **第 0 层**：$n$
  - **第 1 层**：$(1/3)n + (2/3)n = n$
  - **第 2 层**：$(1/9 + 2/9 + 2/9 + 4/9)n = n$
- **规律**：在树完全填满的层，每层总代价恒为 $n$。

### 2. 树高分析

由于分裂不均，树的叶子节点不在同一层：

- **最短路径（最左）**：$n \to n/3 \to n/9 \dots$ 深度约为 $\log_3 n$。
- **最长路径（最右）**：$n \to 2n/3 \to 4n/9 \dots$ 深度约为 $\log_{3/2} n$。

### 3. 最终复杂度

- **推导**：总工作量 $\le$ 每一层的最大代价 $\times$ 树的最大深度。
- **计算**：$T(n) \le n \cdot \log_{3/2} n$。
- **结论**：$T(n) = \Theta(n \log n)$。

------

## 三、 终极工具：广义主定理 (Akra-Bazzi Theorem)

*这是解决复杂递归最通用的数学方法，适用于 $T(n) = \sum a_i T(b_i n) + g(n)$。*

### 1. 核心步骤

1. 求核心常数 $p$：

   解方程：$a_1 b_1^p + a_2 b_2^p + \dots + a_k b_k^p = 1$。

   例如对 $T(n) = T(n/3) + T(2n/3) + n$，解为 $(1/3)^p + (2/3)^p = 1$，显然 $p=1$。

2. 代入积分公式：

   

   $$T(n) = \Theta\left( n^p \left( 1 + \int_1^n \frac{g(u)}{u^{p+1}} du \right) \right)$$

### 2. 案例计算

以 $T(n) = T(n/3) + T(2n/3) + n$ 为例：

- 已知 $p=1, g(u)=u$。
- 代入积分：$\int_1^n \frac{u}{u^2} du = \int_1^n \frac{1}{u} du = \ln n$。
- 结果：$T(n) = \Theta(n(1 + \ln n)) = \Theta(n \log n)$。

------

**总结表：如何选择方法？**

| **情况**                          | **推荐方法**   | **理由**       |
| --------------------------------- | -------------- | -------------- |
| 标准形式 $aT(n/b) + n^d$          | **主定理**     | 最快，直接查表 |
| 子问题规模不均（如 $n/3 + 2n/3$） | **递归树法**   | 直观，易于理解 |
| 极其复杂的 $f(n)$ 或混合比例      | **广义主定理** | 严谨，万能公式 |
