# 数据管理基础

**数据**是指具有一定**语义**含义，并且可以被记录下来的已知信息。

**数据库**：是指长期存储在计算机内、有组织的、可共享的大量数据的集合。数据库中的数据按一定的数据模型、描述和存储，具有较小的数据冗余、较高的数据独立性和易扩展性，并可为各种用户共享。

**数据库管理系统**：位于用户（应用程序）与数据库（操作系统）之间的一层数据管理系统，是一种用于管理数据库的大型计算机基础软件。

**数据库系统**：由数据库、数据管理系统、数据库管理员、支撑系统运行所必需的系统软件和硬件平台组成的存储、管理、处理和维护数据的系统。

**数据库应用系统**：由数据库系统、应用开发工具、应用系统、数据库用户组成的计算机系统。



**数据库管理系统**：

+ 数据定义
+ 数据组织、存储和管理
+ 数据操纵
+ 数据库的事务管理和运行管理
+ 数据库的建立和维护
+ 其他

两层为**客户-服务器**架构，三层为**浏览器-应用服务器/数据库服务器**架构

**数据冗余存储**：同一个数据项，在数据库中的不同地方出现重复存储

**数据的一致性与不一致性**：同一个数据项在不同的地方都具有相同的值；否则

**数据库系统的特点**：

+ 数据结构化
+ 数据的共享性高，冗余度低且易扩充
+ 数据独立性高
+ 数据由数据库管理系统统一管理和控制

**数据模型**：

+ 用于描述现实世界中的数据及其相互关系，并定义在这些数据上可执行的操作。
+ 三要素：数据结构，数据操作和数据约束
+ 三种类型：概念模型、逻辑模型、物理模型

# SQL

## 概述

### 1. SQL 语言概述

- **定义与地位**：SQL（结构化查询语言）是关系数据库的标准语言，具有极强的功能 。
- **核心特点**：
  - **综合统一**：集数据定义（DDL）、数据操纵（DML）、数据控制（DCL）功能于一体 。
  - **高度非过程化**：用户只需提出“做什么”，无需了解具体的存取路径 。
  - **面向集合的操作方式**：操作对象和结果可以是元组的集合 。
  - **双重使用方式**：既可以独立用于交互，也可以嵌入到高级语言（如C、Java）中 。
- **核心动词**：主要包括 `CREATE`、`DROP`、`ALTER`（定义）；`SELECT`（查询）；`INSERT`、`UPDATE`、`DELETE`（操作）；以及 `GRANT`、`REVOKE`（控制） 。

### 2. 数据库对象命名与三级模式

- **层次结构**：数据库系统采用“实例 -> 数据库 -> 模式 -> 表/视图/索引”的层次化命名机制 。
- **三级模式结构**：SQL 支持关系数据库的三级模式结构，其中外模式对应视图，模式对应基本表，内模式对应存储文件 。

### 3. SQL 数据定义功能（核心内容）

- **模式（Schema）定义**：
  - 定义模式实际上是在定义一个命名空间 。
  - 使用 `CREATE SCHEMA` 创建模式，使用 `DROP SCHEMA`（可配合 `CASCADE` 或 `RESTRICT`）删除模式 。
- **基本表（Table）定义与维护**：
  - **创建**：使用 `CREATE TABLE` 定义表名、列名、数据类型及完整性约束（如主码 `PRIMARY KEY`、外码 `FOREIGN KEY`、唯一性 `UNIQUE`） 。
  - **修改**：使用 `ALTER TABLE` 增加新列、修改列定义或删除约束 。
  - **删除**：使用 `DROP TABLE` 删除表及其数据 。
- **索引（Index）管理**：
  - **目的**：加快查询速度 。
  - **操作**：涵盖了创建索引（`CREATE INDEX`）、重命名索引（`ALTER INDEX`）以及删除索引（`DROP INDEX`）的语法及实例 。

### 4. 数据字典与实例

- **数据字典**：它是关系数据库管理系统内部的一组系统表，记录了所有对象的定义信息、操作权限及统计信息 。
- **案例参考**：文件中还介绍了华为 **GaussDB** 和蚂蚁集团 **OceanBase** 数据库中数据字典的具体实现与视图类型 。

## 查询

### 1. SQL查询语句概览

SQL查询的核心是**映像语句（Mapping Statement）**，其一般格式如下 ：

```sql
SELECT [ALL|DISTINCT] <目标列表达式> [AS 别名] -- 投影
FROM <表名/视图名/子查询> [AS 别名]        -- 范围
[WHERE <条件表达式>]                        -- 元组选择/连接条件
[GROUP BY <列名> [HAVING <统计条件>]]      -- 分组与分组过滤
[ORDER BY <列名> [ASC|DESC]];              -- 排序
```

**执行顺序**：通常为 `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY` 。

------

### 2. 单表查询 (Single Table Query)

#### 2.1 投影（选择列）

- **全部列**：使用 `*` 。
- **计算值与函数**：可以投影常量、表达式或内置函数（如 `LOWER()` 转换小写） 。
- **去重**：使用 `DISTINCT` 消除重复行 。

**示例 [例3.20]：** 查询学生姓名、出生年份（假设2014年）及小写系名 。

```sql
SELECT Sname, 'Year of Birth:', 2014-Sage, LOWER(Sdept) 
FROM Student;
```

#### 2.2 元组选择（WHERE子句谓词）

| **谓词类型** | **示例 SQL**                        | **备注**                             |
| ------------ | ----------------------------------- | ------------------------------------ |
| **比较大小** | `WHERE Sage < 20`                   | `=`, `>`, `<`, `>=`, `<=`, `!=`      |
| **范围查询** | `WHERE Sage BETWEEN 20 AND 23`      | 包含边界值                           |
| **集合查询** | `WHERE Sdept IN ('CS', 'MA', 'IS')` | 匹配列表中的任一值                   |
| **字符匹配** | `WHERE Sname LIKE '刘%'`            | `%`代表任意长度字符，`_`代表单个字符 |
| **空值查询** | `WHERE Grade IS NULL`               | **不可**用 `= NULL` 代替             |

#### 2.3 排序与聚合

- **排序 (ORDER BY)**：默认升序 (`ASC`)，降序需指定 `DESC` 。
- **聚合函数**：`COUNT(*)` 统计元组数，`SUM` 求和，`AVG` 平均值，`MAX/MIN` 最大/最小值 。
  - 注意：聚合函数通常只能用在 `SELECT` 或 `HAVING` 子句中 。

------

### 3. 分组统计查询 (GROUP BY)

`GROUP BY` 将查询结果按一列或多列值分组，聚合函数将作用于每个小组 。

**示例 [例3.47]：** 查询选修了3门以上课程的学生学号 。

```sql
SELECT Sno 
FROM SC 
GROUP BY Sno 
HAVING COUNT(*) > 3; -- HAVING用于过滤分组结果，不能用WHERE
```

------

### 4. 连接查询 (Join Query)

连接查询涉及两个或多个表的关联。

- **等值/自然连接**：在 `WHERE` 子句中定义等值条件 。
- **自连接**：同一张表与其自身连接，必须使用**别名**区分 。
- **外连接 (Outer Join)**：保留不满足连接条件的元组 。

**示例 [例3.53]：** 左外连接查询，即使学生未选课也列出其信息 。

```sql
SELECT Student.Sno, Sname, Cno, Grade 
FROM Student LEFT OUTER JOIN SC ON (Student.Sno = SC.Sno);
```

------

### 5. 嵌套查询 (Nested Query)

将一个查询块嵌入到另一个查询块中。

- **IN 谓词**：子查询返回一个集合 。
- **ANY / ALL 谓词**：用于与子查询结果集进行比较 。
- **EXISTS 谓词**：判断子查询是否有结果返回（存在性测试），常用于实现逻辑中的全称量词（$\forall$） 。

**示例 [例3.56]：** 查询选修了“信息系统”课程的学生学号和姓名（嵌套三层） 。

```sql
SELECT Sno, Sname FROM Student
WHERE Sno IN (
    SELECT Sno FROM SC WHERE Cno IN (
        SELECT Cno FROM Course WHERE Cname='信息系统'
    )
);
```

------

### 6. 集合查询 (Set Operations)

对多个查询结果集进行并、交、差运算。要求参与运算的各结果表列数相同且数据类型一致 。

- **UNION**：并操作（自动去重） 。
- **INTERSECT**：交操作 。
- **EXCEPT**：差操作 。

**示例 [例3.67]：** 查询既选修了课程1又选修了课程2的学生 。

```sql
SELECT Sno FROM SC WHERE Cno='1'
INTERSECT
SELECT Sno FROM SC WHERE Cno='2';
```

## 事务

### 1. 什么是事务？

**事务** 是数据库管理系统（DBMS）执行过程中的一个逻辑单位，由一系列 SQL 语句组成。这些操作要么**全做**，要么**全不做**，是一个不可分割的工作单元。

### 2. 事务的 ACID 特性

这是事务处理的四个基本要素：

| **特性** | **名称**                 | **描述**                                                     |
| -------- | ------------------------ | ------------------------------------------------------------ |
| **A**    | **原子性 (Atomicity)**   | 事务中的操作要么全部完成，要么全部不完成。                   |
| **C**    | **一致性 (Consistency)** | 事务执行前后，数据库必须保持一致性状态（如账户总额不变）。   |
| **I**    | **隔离性 (Isolation)**   | 并发执行的事务之间不能相互干扰。                             |
| **D**    | **持续性 (Durability)**  | 一旦事务提交，对数据的改变是永久性的，即使系统崩溃也不会丢失。 |

------

### 3. SQL 中的事务控制语句

在 SQL 中，事务通常不需要显式定义“开始”，但需要显式地定义“结束”方式：

#### A. 提交 (COMMIT)

当事务中的所有操作都成功完成时，使用 `COMMIT`。此时，事务对数据库的所有修改将永久生效。

**SQL 示例：**

```sql
BEGIN TRANSACTION;  -- 开始事务（部分数据库如GaussDB支持）
UPDATE Account SET Balance = Balance - 100 WHERE UserID = 'A';
UPDATE Account SET Balance = Balance + 100 WHERE UserID = 'B';
COMMIT;            -- 确认提交，钱正式划转
```

#### B. 回滚 (ROLLBACK)

如果在事务执行过程中发生错误（如余额不足、断电等），使用 `ROLLBACK`。此时，系统将撤销所有已做的操作，恢复到事务开始前的状态。

**SQL 示例：**

```sql
BEGIN TRANSACTION;
UPDATE Account SET Balance = Balance - 100 WHERE UserID = 'A';
-- 假设此时发现 B 账户不存在，程序触发错误
ROLLBACK;          -- 撤销操作，A 的账户余额恢复原样
```

------

### 4. 事务与数据更新的关系

在进行 `INSERT`、`UPDATE`、`DELETE` 操作时，事务的作用尤为重要：

- **批量插入**：如果插入 1000 条记录时第 999 条报错，可以通过事务回滚确保数据库里一条“脏数据”都没有。
- **数据一致性**：在涉及多张表的级联更新时（例如修改学生学号同时更新成绩表），事务保证了关联数据的同步。

### 5. 补充：视图更新的限制

课件末尾提到，并不是所有视图都可以更新。如果视图的定义涉及到**聚合函数（如 AVG）\**或\**多表连接**，通常无法直接通过视图进行 `UPDATE`，因为系统无法确定如何将这些更改唯一地转换回基本表的操作。

> **💡 小贴士**：在实际开发中，默认情况下许多数据库处于“自动提交（Autocommit）”模式。如果你要执行多条关联语句，记得先关闭自动提交或显式开启事务，否则一旦中间出错，手动“修数据”可是很头疼的！
