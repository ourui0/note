名词分析法 —— Abbott ⽅法 [Abbott 1983]
 
五步⾛
步骤 活动 说明
① 收集⽤例描述⽂本收集所有主要⽤例描述
② 标记名词和名词短语逐句⽤ [] 标记所有名词
③ 去除重复 汇总成列表，合并同义词
④ 筛选 运⽤筛选准则排除不适合的名词
⑤ 确认 与业务专家确认候选类列表
 
示例
"[顾客]选择'去结算'。[系统]显示[购物⻋]中的[商品清单]，包括每件[商品]的[名称]、[单价]、[数量]…[系统]⽣成[订单]"

对象约束语⾔ O CL  —— 让约束精确化 [O M G U M L  2.5]
为什么需要 OCL ？
UML 图能表达结构，但⽆法精确表达约束规则：
约束 U M L  图的局限 O CL  的表达
订单总⾦额必须 >  0 类图画不出 inv: self.totalAmount > 0
购物⻋每件商品 1-99 件 多重性标不了 inv: self.items->forAll(i | i.qty <= 99)
已发货不可取消 状态图⽤⾃然语⾔，有歧义pre: self.status <> #SHIPPED
 
OCL  核⼼特点
声明式：只说"是什么"，不说"怎么做"
⽆副作⽤：不修改模型状态，只做断⾔和查询
依附于 UML：附加在类图、状态图等模型元素上

O CL  核⼼语法 [O M G U M L  2.5]
1. 不变量（Invariant）—— 对象始终满⾜的条件
context Order
inv: self.lineItems->size() >= 1        -- 订单⾄少含⼀个明细⾏
inv: self.totalAmount > 0               -- 总⾦额为正
2. 前置/后置条件 —— 操作契约的形式化
context Order::pay()
pre:  self.status = OrderStatus::PENDING_PAYMENT

public void pay() {
  if (status != PENDING_PAYMENT)
    throw new IllegalStateException();
  status = PAID;
  deductInventory();       // 动作：扣减库存
}
// 已⽀付  → 已发货
public void ship(String trackingNo) {
  if (status != PAID)
    throw new IllegalStateException();
  status = SHIPPED;
}
// 多条  → 已取消（守卫条件不同）
public void cancel() {
  if (status == PENDING_PAYMENT) {
    status = CANCELLED;
    releaseInventory();    // 释放库存
  } else if (status == PAID) {
    status = CANCELLED;
    releaseInventory();
    initiateRefund();      // 发起退款
  } else throw new IllegalStateException();
} 43
