## 1. 并发

### 1.1 什么是线程？线程和进程有什么区别？ ★★★

`[课件原话]` “并发的基本单位是线程。”  
`[课件原话]` “什么是线程：共享内存的执行流。”  
`[课件原话]` “拥有独立的上下文和栈帧列表，共享全局变量、堆空间。”

`[自总结]` 线程是 CPU 调度执行的基本单位，同一进程内线程共享地址空间、全局变量、堆和打开文件等资源，但每个线程有自己的寄存器上下文、栈和执行位置。进程更像资源容器，线程更像执行流。

`关键词`：执行流、调度单位、共享地址空间、共享堆、独立栈、独立寄存器、进程是资源容器。

### 1.2 为什么多线程程序结果可能不确定？ ★★★

`[课件原话]` “多个线程就是多个共享内存的状态机。”  
`[课件原话]` “状态迁移为调度器任意选择一个线程执行一步。”  
`[课件原话]` “线程的先后执行顺序是不确定的。”

`[自总结]` 多线程共享内存，调度器可能在很多位置切换线程。如果多个线程同时读写共享变量，且没有同步约束，最终结果会依赖具体调度顺序，所以出现不确定性。

`关键词`：共享内存、调度不确定、执行交错、共享变量、无同步、结果依赖调度。

### 1.3 什么是临界区和竞态条件？ ★★★

`[课件原话]` “临界区：访问共享资源的一段代码，资源通常是一个变量或数据结构。”  
`[课件原话]` “竞态条件：出现在多个执行线程大致同时进入临界区时，它们都试图更新共享的数据结构，导致非预期的结果。”

`[自总结]` 临界区是访问共享状态的代码段；竞态条件是多个线程以不可控顺序访问共享状态，使结果取决于调度。解决核心是用互斥锁等机制保证同一时刻只有一个线程进入相关临界区。

`关键词`：临界区、共享资源、竞态条件、结果依赖调度、互斥、同一时刻一个线程。

### 1.4 互斥锁解决什么问题？它本身为什么不自动保证正确？ ★★★

`[课件原话]` “如何设计机制使得临界区避免出现竞态条件是并发的重要主题。”  
`[课件原话]` “lock 和 unlock 没有真正意义上的保护临界区的共享资源。”  
`[课件原话]` “互斥锁的正确性依赖于你是理智的合作者。”

`[自总结]` 锁提供进入临界区的互斥机制，但程序员必须把所有访问同一共享资源的代码都放在同一把锁保护下，并正确成对调用 `lock/unlock`。如果某处绕过锁访问共享变量，仍然会出现竞态。

`关键词`：保护临界区、同一把锁、所有共享访问、成对 `lock/unlock`、绕过锁仍会竞态。

### 1.5 自旋锁和阻塞互斥锁有什么区别？ ★★

`[课件原话]` “当一个线程在自旋等待时，它一定能够最终进入临界区吗？不一定。”  
`[课件原话]` “除了进入临界区的线程，其他处理器上的线程都在空转。”

`[自总结]` 自旋锁拿不到锁时反复循环检查，适合临界区很短、等待时间很短、内核中不能睡眠的场景；阻塞互斥锁拿不到锁时让线程睡眠，避免浪费 CPU，适合用户态或等待较长的场景。

`关键词`：自旋、忙等待、不睡眠、短临界区、浪费 CPU；阻塞、睡眠、让出 CPU、等待较长。

### 1.6 什么是条件变量？为什么要配合互斥锁使用？ ★★★

`[课件原话]` “条件变量：用于标记某个用于同步条件的变量。”  
`[课件原话]` “cond_wait 调用之前默认假设已经持有锁。”  
`[课件原话]` “调用之后原子的阻塞线程和释放锁，被唤醒时重新 acquire the lk。”

`[自总结]` 条件变量用于等待某个共享条件成立，例如队列非空。它必须和互斥锁配合：锁保护条件检查，`wait` 原子地释放锁并睡眠，避免检查条件和睡眠之间发生丢失唤醒。被唤醒后要重新检查条件，通常写成 `while (!condition) wait(...)`。

`关键词`：等待条件、配合互斥锁、原子释放锁并睡眠、避免丢失唤醒、醒来重查、`while`。

### 1.7 什么是信号量？为什么说它有“状态记忆”？ ★★★

`[课件原话]` “信号量是更加容易使用的同步工具。”  
`[课件原话]` “其具有状态记忆，可以看成初始资源。”

`[自总结]` 信号量是带整数计数的同步原语。`P/wait` 表示申请一个资源，若计数不足则阻塞；`V/post` 表示释放一个资源并可能唤醒等待线程。它有状态记忆：即使 `post` 先发生，计数也会保留，后来的 `wait` 可以直接通过。

`关键词`：整数计数、`P/wait` 申请资源、`V/post` 释放资源、阻塞/唤醒、状态记忆、资源数量。

### 1.8 条件变量和信号量有什么区别？ ★★★

`[课件原话]` “条件变量可以帮助实现适用于任何同步条件（注意使用方法，需要配合互斥锁）。”  
`[课件原话]` “信号量是更加容易使用的同步工具，其具有状态记忆，可以看成初始资源。”

`[自总结]` 条件变量适合表达复杂条件，需要互斥锁保护条件并用 `while` 反复检查；信号量适合表达资源数量或事件次数，内部带计数。条件变量的 `signal` 在没有等待者时通常不会保存；信号量的 `post` 会增加计数。

`关键词`：条件变量等复杂条件、需要锁、`while` 重查；信号量数资源、保存次数、状态记忆。

### 1.9 什么是安全性和活性？ ★★★

`[课件原话]` “死锁和饿死都关乎活性，死锁和饿死并没有违背安全性！”  
`[课件原话]` “饿死即为一个线程在有限时间内无法行进。”  
`[课件原话]` “死锁是一类特殊的饿死，其达成的条件是多个线程形成一个等待环。”

`[自总结]` 安全性关注“坏事不会发生”，例如两个线程不会同时进入临界区。活性关注“好事最终会发生”，例如等待锁的线程最终能继续执行。死锁、饿死、活锁通常是活性问题，不一定破坏互斥安全性。

`关键词`：安全性=坏事不发生、互斥正确；活性=好事最终发生、能前进；死锁/饥饿/活锁。

### 1.10 什么是内存一致性模型？ ★★

`[自总结]` 内存一致性模型规定多处理器/多线程程序中，一个线程对内存的读写何时、以什么顺序被其他线程看到。最直观的是顺序一致性：所有线程操作像按某个全局顺序交错执行，且每个线程内部顺序不变。实际硬件和编译器可能重排或缓存，因此需要锁、原子操作、内存屏障等同步手段建立可见性和顺序关系。

`关键词`：多核可见性、读写顺序、顺序一致性、全局顺序、线程内顺序、重排序、同步建立顺序。

## 2. 虚拟化：进程与调度

### 2.1 `fork`、`execve`、`exit` 分别做什么？ ★★★

`[课件原话]` “进程最重要的三类系统调用：fork — 进程的创建；execve — 进程的改变；exit — 进程的删除。”

`[自总结]` `fork` 创建子进程，父子从 `fork` 返回处继续执行，只是返回值不同；`execve` 用新程序替换当前进程映像，不创建新进程；`exit` 终止当前进程并释放资源、留下退出状态供父进程回收。

`关键词`：`fork` 创建子进程、父子都返回、返回值不同；`execve` 替换映像、不创建进程；`exit` 结束回收。

### 2.2 为什么 shell 执行命令通常要 `fork + execve`？ ★★★

`[自总结]` 因为 `execve` 会替换当前进程。如果 shell 直接 `execve("ls")`，shell 自己会变成 `ls`，无法继续接收命令。因此 shell 先 `fork` 子进程，让子进程 `execve` 成目标程序，父进程 shell 保留并等待或继续运行。

`关键词`：`execve` 替换当前进程、shell 保留、子进程执行命令、父进程 `wait`、命令行模型。

### 2.3 什么是写时复制 COW？为什么能优化 `fork`？ ★★★

`[课件原话]` “写时复制。”  
`[课件原话]` “早期的 fork 就是这么无脑的复制父进程的一切，但人们发现这个过程是低效的。”  
`[课件原话]` “立即执行 execve 会加载新的可执行文件，重置地址空间，因此，之前的内存拷贝完全没有意义。”

`[自总结]` COW 让父子进程在 `fork` 后先共享物理页，并把共享页标为只读。某一方写入时触发异常，内核才复制被写的页。这样避免 `fork` 时立刻复制整个地址空间，尤其适合 `fork` 后马上 `execve` 的场景。

`关键词`：共享物理页、只读标记、写入触发异常、按页复制、优化 `fork`、避免无意义复制。

### 2.4 什么是上下文切换？为什么有开销？ ★★★

`[自总结]` 上下文切换是 OS 保存当前进程/线程的 CPU 上下文，并恢复另一个进程/线程上下文的过程。它的开销包括保存和恢复寄存器、切换内核数据结构、切换地址空间、影响缓存和 TLB 等。上下文切换让多个任务共享 CPU，但过于频繁会降低有效执行时间。

`关键词`：保存现场、恢复现场、寄存器、地址空间、页表、TLB/cache 开销、共享 CPU。

### 2.5 什么是调度？常见调度指标有哪些？ ★★★

`[课件原话]` “调度：为了满足既定目标，对计算任务进行资源分配的行为。”  
`[课件原话]` 调度指标包括 “CPU 利用率”“公平”“吞吐量”“周转时间”“等待时间”“响应时间”。

`[自总结]` CPU 调度是在多个就绪进程/线程之间决定谁运行。批处理系统偏重吞吐量、周转时间和等待时间；交互系统偏重响应时间；通用系统还要考虑公平性和优先级。

`关键词`：就绪队列、选择谁运行、CPU 分配、吞吐量、周转时间、等待时间、响应时间、公平性。

### 2.6 什么是机制与策略分离？ ★★★

`[课件原话]` “操作系统中的一个重要设计思想：机制与策略的分离。”  
`[课件原话]` “策略表示可以做什么；机制表示怎么做。”

`[自总结]` 机制提供完成某事的基本能力，例如上下文切换、定时器中断、队列操作；策略决定如何选择，例如 FCFS、SJF、RR、优先级。分离后可以在同一机制上替换不同策略，降低复杂度并提高灵活性。

`关键词`：机制=怎么做、策略=选哪个、上下文切换、定时器中断、调度算法、模块化、灵活。

### 2.7 SJF 和 SRTF 的区别是什么？ ★★★

`[课件原话]` “SJF：需要运行时间最短的优先被调度。”  
`[课件原话]` “SRTF：最短任务优先的可抢占版本，始终选择剩下需要时间最短的进程。”

`[自总结]` SJF 是非抢占式，选中短作业后通常运行到完成或阻塞；SRTF 是抢占式，如果新到达进程剩余时间更短，会抢占当前进程。SJF/SRTF 平均等待时间较好，但需要估计运行时间，长任务可能饥饿。

`关键词`：SJF 非抢占、最短作业；SRTF 抢占、剩余时间最短；估计运行时间、平均等待短、长作业饥饿。

### 2.8 时间片轮转 RR 的优缺点是什么？ ★★

`[自总结]` RR 给每个就绪进程一个时间片，时间片用完就切换到队尾，适合交互式系统，响应较公平。时间片太大会退化为 FCFS，响应变差；时间片太小会导致上下文切换过多，浪费 CPU。

`关键词`：时间片、轮转、队尾、公平、响应好、太大像 FCFS、太小切换开销大。

### 2.9 优先级调度的问题是什么？如何缓解？ ★★

`[自总结]` 优先级调度让高优先级任务先运行，能表达任务重要性。但低优先级任务可能长期得不到 CPU，发生饥饿。常用缓解方法是 aging，即等待时间越长逐步提高优先级。

`关键词`：高优先级先运行、低优先级饥饿、aging 老化、等待越久优先级提高。

### 2.10 EDF 是什么？为什么属于实时调度？ ★★

`[课件原话]` “EDF：根据截止期限分配优先级。”  
`[课件原话]` “截止期限越早，优先级越高；截止期限越晚，优先级越低。”

`[自总结]` EDF 即最早截止期限优先，动态按任务 deadline 调整优先级，适合实时系统。它关注任务是否能在截止时间前完成，而不只是平均等待时间。

`关键词`：Earliest Deadline First、deadline、越早优先级越高、动态优先级、实时调度。

## 3. 虚拟化：内存

### 3.1 什么是虚拟内存？为什么需要虚拟内存？ ★★★

`[课件原话]` “以虚拟内存抽象为核心的内存管理。”  
`[课件原话]` “所有软件均使用虚拟地址，无法直接访问物理地址。”

`[自总结]` 虚拟内存把每个进程看到的地址空间和真实物理内存分离。它提供隔离、保护、简化编程、支持按需分页和共享，使每个进程好像独占连续内存。

`关键词`：虚拟地址、物理地址、地址空间隔离、保护、按需分页、共享、独立视图。

### 3.2 什么是分页？虚拟地址如何划分？ ★★★

`[课件原话]` “每个进程都有一个页表。”  
`[课件原话]` “每个页表项包含一个物理页号，也叫物理帧号，指示每个页在物理内存中的基地址。”

`[自总结]` 分页把虚拟地址空间分成固定大小的页，把物理内存分成同样大小的页框。虚拟地址通常划分为 `虚拟页号 VPN + 页内偏移 offset`。页表用 VPN 找到 PFN，再加上页内偏移形成物理地址。

`关键词`：虚拟页、物理页框、固定大小、VPN、offset、页表、PFN、地址翻译。

### 3.3 什么是多级页表？为什么能节省空间？ ★★★

`[课件原话]` “使用多级页表减少空间占用。”  
`[课件原话]` “若某级页表中的某条目为空，那么对应的下一级页表无需存在。”  
`[课件原话]` “实际应用的虚拟地址空间大部分都未被使用，因此无需分配页表。”

`[自总结]` 多级页表把一张大页表拆成页目录和若干下级页表。只为实际使用的虚拟地址区域分配下级页表，从而节省稀疏地址空间中的页表内存。代价是一次地址翻译可能需要多次访存，所以依赖 TLB 加速。

`关键词`：页目录、下级页表、稀疏地址空间、空项不分配、节省内存、多次访存、依赖 TLB。

### 3.4 什么是 TLB？TLB miss 是否等于缺页？ ★★★

`[课件原话]` “TLB：Translation Look-aside Buffers，地址转换旁路缓冲。”

`[自总结]` TLB 是 MMU 中缓存页表项的小型高速缓存，保存最近的 `VPN -> PFN` 映射，用于加速地址翻译。TLB miss 只是 TLB 没有缓存该映射，之后可能查页表并填入 TLB；只有页表项无效或页面不在内存时，才发生缺页异常。

`关键词`：页表项缓存、MMU、`VPN -> PFN`、加速翻译、TLB miss、查页表、不等于缺页。

### 3.5 什么是缺页异常？处理流程是什么？ ★★★

`[课件原话]` “如果页面在物理内存中，则直接进行地址转换。”  
`[课件原话]` “如果不在，则发生缺页异常，操作系统被调用来处理该异常。”  
`[课件原话]` “检测并将页面加载到内存中，然后重新执行指令。”

`[自总结]` 缺页异常发生在进程访问的虚拟页不在 物理内存中。OS 检查地址是否合法，找到空闲页框或选择牺牲页，必要时把脏页写回磁盘，再把所需页读入内存，更新页表/TLB，最后重新执行导致缺页的指令。

`关键词`：页不在内存、陷入内核、检查合法性、找页框、victim、脏页写回、调页、更新页表、重启指令。

### 3.6 页面置换算法解决什么问题？常见算法如何理解？ ★★★

`[课件原话]` “如果没有空闲帧，则运行页面置换以选择一个 victim。”  
`[课件原话]` “如果所选帧是脏的，则将页面安排转移到磁盘。”

`[自总结]` 页面置换在内存页框不够时选择一个页面换出。FIFO 换出最早进入内存的页，简单但可能有 Belady 异常；LRU 换出最近最久未使用的页，符合局部性但精确实现昂贵；Clock/Aging 用引用位或历史寄存器近似 LRU；LFU 按访问频率选择牺牲页。

`关键词`：内存满、选择 victim、FIFO 最早进入、LRU 最近最久未用、LFU 次数最少、Clock/Aging 近似 LRU、脏页代价。

### 3.7 什么是工作集和抖动？ ★★

`[课件原话]` “工作集：其在时间段内使用的内存页集合也被视为其在未来下一个时间内会访问的页集。”  
`[课件原话]` “如果可用内存太小，无法容纳整个工作集，则会发生抖动。”

`[自总结]` 工作集表示进程近期活跃使用的页面集合。如果系统给进程的页框少于工作集大小，进程会频繁缺页，CPU 大量时间花在换页上，这就是抖动。

`关键词`：近期页面集合、局部性、页框不足、频繁缺页、换页 I/O、抖动。

## 4. 持久化

### 4.1 文件系统解决什么问题？ ★★★

`[课件原话]` “文件是操作系统创建的逻辑存储单元，用于存储信息。”  
`[课件原话]` “提供了一种在磁盘上存储信息并随后读取的抽象机制。”

`[自总结]` 文件系统把原始块设备抽象成文件和目录，提供命名、权限、读写接口、空间分配、路径解析、缓存和可靠性机制，使用户程序不用直接操作磁盘扇区。

`关键词`：文件/目录抽象、命名、权限、读写接口、空间分配、路径解析、缓存、持久化。

### 4.2 什么是文件描述符？为什么需要它？ ★★★

`[课件原话]` “文件描述符：操作系统分配给一个进程打开的文件的一个唯一数字（每个进程私有），用于引用该文件。”  
`[课件原话]` “避免在每次访问时解析文件名和检查权限。”

`[自总结]` `fd` 是进程访问已打开文件的句柄。`open` 完成路径解析、权限检查并建立内核数据结构，之后 `read/write` 用整数 `fd` 就能找到对应打开文件，避免反复查路径。

`关键词`：进程私有整数、句柄、已打开文件、`open`、路径解析、权限检查、`read/write`。

### 4.3 文件描述符表、打开文件表、inode 表三者关系是什么？ ★★★

`[课件原话]` “文件描述符表（每个进程）：为进程打开的每个文件描述符创建一个条目，指向打开文件表的指针。”  
`[课件原话]` “打开文件表（系统范围）：为每个打开的文件创建一个条目，文件偏移量、访问模式、与文件打开相关的标志、inode 指向的指针。”  
`[课件原话]` “inode 表（系统范围）：为每个 inode 点创建一个条目，文件属性（类型、大小、权限、时间戳等）。”

`[自总结]` 进程 fd 表是每进程私有的整数索引；系统打开文件表保存打开状态，尤其是文件偏移；inode 表保存文件本身的元数据和数据块位置。`fork` 或 `dup` 后，多个 fd 可能指向同一个打开文件表项，因此共享文件偏移。

`关键词`：fd 表每进程私有、打开文件表系统范围、文件偏移、inode 指针、inode 元数据、`fork/dup` 共享偏移。

### 4.4 `read/write` 文件时 OS 大致做什么？ ★★★

`[课件原话]` “Path -> inode；File offset -> Disk block；Permission check。”  
`[课件原话]` “writei：根据文件对应的编号和偏移量来写入对应的字符串。”  
`[课件原话]` “bmap 返回 inode 第 offset 索引的磁盘块号（没有则分配）。”

`[自总结]` `write(fd, buf, n)` 会通过 fd 找到打开文件表项，再找到 inode；根据当前文件偏移把逻辑位置映射到磁盘块，必要时分配新块；把用户缓冲区的 n 字节写入页缓存/缓冲区；更新文件偏移、文件大小、时间等元数据。数据不一定立刻落盘，除非 `fsync` 或文件系统策略要求。

`关键词`：fd、打开文件表、inode、文件偏移、逻辑块到磁盘块、分配数据块、用户缓冲区、更新 inode、不一定立刻落盘。

### 4.5 什么是 inode？它保存什么？ ★★★

`[课件原话]` “文件元数据（属性）：数据块位置、大小、时间、所有者、保护信息、链接信息。”  
`[课件原话]` “inode 文件系统负责维护路径、目录、inode、权限、空闲空间和文件到磁盘块的映射。”

`[自总结]` inode 是 Unix 文件系统中描述文件的核心元数据结构，保存文件类型、权限、所有者、大小、时间、链接计数以及数据块指针等。文件名通常不在 inode 中，而在目录项中；目录项把文件名映射到 inode 号。

`关键词`：文件元数据、权限、大小、时间、链接计数、数据块指针、不存文件名、目录项映射。

### 4.6 目录是什么？路径解析如何进行？ ★★

`[自总结]` 目录本身也是文件，内容是若干目录项，每个目录项通常记录 `文件名 -> inode号`。路径解析从根目录或当前目录开始，逐级读取目录内容，查找下一级名字对应的 inode，直到找到目标文件。

`关键词`：目录也是文件、目录项、`文件名 -> inode号`、路径解析、逐级查找、根目录/当前目录。

### 4.7 硬链接和软链接有什么区别？ ★★★

`[课件原话]` “link：从现有文件创建一个链接（硬链接）到路径名，允许文件出现在多个目录中。”  
`[课件原话]` “有两种链接：硬链接；符号链接或软链接。”

`[自总结]` 硬链接是在目录中增加一个名字，直接指向同一个 inode，会增加 inode 的链接计数；删除一个硬链接只删除一个目录项，只要链接计数不为 0，文件数据仍在。软链接是一个特殊文件，内容是目标路径，有自己的 inode；可以跨文件系统、可指向目录，但目标路径不存在时会变成悬空链接。

`关键词`：硬链接=同 inode、目录项别名、链接计数、删除一个仍在；软链接=特殊文件、保存路径、独立 inode、可跨文件系统、悬空。

### 4.8 inode 多级索引为什么需要？如何答最大文件大小？ ★★★

`[自总结]` inode 要同时高效支持小文件和大文件，所以常用直接指针、一级间接指针、二级间接指针、三级间接指针。小文件直接用 inode 内指针定位，避免额外读索引块；大文件通过间接索引扩展容量。若块大小为 `B`，指针大小为 `P`，每个索引块可放 `B/P` 个指针，最大文件大小按 `直接块数 + 一级容量 + 二级容量 + 三级容量` 乘以块大小计算。

`关键词`：直接指针、一级/二级/三级间接、小文件快、大文件扩展、`B/P`、最大文件大小、索引块不算数据。

### 4.9 什么是 DMA？为什么需要 DMA？ ★★

`[课件原话]` “DMA 由直接内存访问控制。”  
`[课件原话]` “给控制器访问内存和总线的权限。”  
`[课件原话]` “要求它直接在内存和控制器之间传输数据块。”

`[自总结]` DMA 让设备控制器直接在设备和内存之间搬运数据，CPU 只负责发起请求和处理完成中断，不必逐字节拷贝，从而降低 CPU 开销，提高 I/O 效率。

`关键词`：Direct Memory Access、设备到内存、控制器搬运、CPU 发命令、完成中断、减少 CPU 拷贝。

### 4.10 磁盘访问时间由什么组成？ ★★

`[课件原话]` “磁盘访问时间：T I/O = T seek + T rotation + T transfer。”

`[自总结]` 机械磁盘访问时间包括寻道时间、旋转延迟和传输时间。随机访问慢主要因为寻道和旋转延迟；顺序访问更快，因为磁头移动少、传输占主导。

`关键词`：寻道时间、旋转延迟、传输时间、随机访问慢、顺序访问快、磁头移动。

### 4.11 什么是磁盘调度？SCAN 电梯算法如何理解？ ★

`[课件原话]` “I/O 成本高，操作系统历来在决定发往磁盘的 I/O 顺序方面发挥了作用。”  
`[课件原话]` “SCAN：简单地在磁盘上来回移动，按顺序跨磁道处理请求（像电梯一样运行）。”

`[自总结]` 磁盘调度通过重排请求顺序减少磁头移动，提高吞吐量。FCFS 公平但可能寻道长；SSTF 就近服务但可能饥饿；SCAN 像电梯一样沿一个方向处理请求，到端点后反向。

`关键词`：重排 I/O、减少磁头移动、FCFS 按序、SSTF 最近优先、SCAN 到边界反向、LOOK 到最远请求反向。

## 6. 55 字以内概念题速记版

| 概念 | 速记答案 |
| --- | --- |
| 线程 | 线程是共享进程地址空间的执行流，有独立栈和寄存器上下文，是调度基本单位。 |
| 竞态条件 | 多线程无同步访问共享状态，结果依赖调度顺序，可能产生非预期结果。 |
| 临界区 | 访问共享资源的一段代码，需要互斥保护以避免竞态。 |
| 条件变量 | 等待共享条件成立的同步原语，需配合互斥锁并循环检查条件。 |
| 信号量 | 带整数计数的同步原语，`P` 申请资源，`V` 释放资源并可能唤醒等待者。 |
| 安全性 | 保证坏事不会发生，例如不会有两个线程同时进入临界区。 |
| 活性 | 保证好事最终发生，例如等待线程最终能继续执行。 |
| `fork` | 创建子进程，父子从返回处继续执行，返回值不同。 |
| `execve` | 用新程序替换当前进程映像，成功后不返回，不创建新进程。 |
| COW | 父子先共享物理页，写入时才复制对应页，以优化 `fork`。 |
| 上下文切换 | 保存当前任务 CPU 状态并恢复另一任务，使多个任务共享 CPU。 |
| TLB | 页表项高速缓存，缓存 `VPN -> PFN` 映射，加速地址翻译。 |
| 缺页异常 | 访问页不在物理内存时触发，由 OS 调页、更新页表后重试指令。 |
| 多级页表 | 把大页表分层，只为使用区域分配下级页表，节省空间。 |
| 文件描述符 | 进程私有的整数句柄，用于引用已打开文件。 |
| inode | 文件元数据结构，保存权限、大小、时间、链接计数和数据块指针。 |
| 硬链接 | 多个目录项指向同一 inode，共享数据和元数据。 |
| 软链接 | 保存目标路径的特殊文件，有自己的 inode，可跨文件系统但可悬空。 |
| DMA | 设备控制器直接在设备和内存间传输数据，减少 CPU 搬运开销。 |
