## 1. 目标与验收标准

本实验在实验一的词法、语法分析器上增加手写语义分析和类型检查。程序读取一个 C-- 源文件；若词法、语法和语义均正确，不输出任何内容；若存在错误，则将规定格式的诊断输出到 `stdout`，并正常退出（`return 0`）。

完成标准如下：

1. 保留实验一已实现的词法、语法分析功能以及“注释”选做，不额外接受八/十六进制数或指数形式浮点数。
2. 正确识别实验手册列出的 1—17 类语义错误。
3. 仅实现实验二选做 2.3：不同名称的结构体按成员类型序列进行结构等价判断。
4. 不实现选做 2.1（函数声明）和 2.2（局部作用域）。相应反向样例必须表现为未实现状态。
5. 在指定 Ubuntu/Flex/Bison/GCC 环境中可由助教的 `makefile_ref` 编译。
6. 最终 ZIP 顶层只含 `Code/` 与 `report.pdf`，报告不超过三页，最小字号不小于英文 11 磅或中文五号。

## 2. 范围与非目标

### 2.1 必做范围

- 基本类型、数组、结构体和函数的类型表示。
- 变量、函数和结构体标签的符号登记与查找。
- 表达式类型推导、左值判断、函数实参与形参匹配。
- 语句条件、返回值、赋值、运算、数组和结构体访问检查。
- 尽量抑制由一个根本错误引起的级联错误。

### 2.2 明确不实现

- 函数声明及声明/定义一致性检查（选做 2.1）。函数声明仍由语法分析阶段报告 B 类错误。
- 嵌套作用域和遮蔽（选做 2.2）。所有变量和形参共享一个全局命名空间，重复定义报告错误 3。
- 隐式类型转换；`int` 与 `float` 不能互相赋值或混合运算。
- 嵌套函数定义、指针、类型别名以及实验语法之外的 C 语言特性。

## 4. 总体架构

### 4.1 模块职责

- `lexer.l`：沿用实验一词法规则；识别普通 C-- 记号和 `//`、`/* ... */` 注释，继续拒绝未选择的实验一选做词法形式。
- `parser.y`：沿用实验一语法和 AST 构造动作。语法成功后保存根结点，不再直接打印语法树。
- `parser.h` / `parser.c`：提供 AST 结点、结点创建与遍历所需接口；主程序协调词法/语法分析和语义分析。
- `semantic.h`：声明类型、字段、函数签名、符号以及语义分析入口。
- `semantic.c`：实现符号表、类型等价、AST 遍历、表达式类型推导和错误输出。

### 4.2 数据流

```text
源文件 → Flex 词法分析 → Bison 语法分析 → AST
                                      ↓（仅无词法/语法错误时）
                              语义遍历与类型检查
                                      ↓
                         无错误：静默；有错误：stdout
```

若词法或语法分析已经失败，不运行语义分析，避免在不完整 AST 上产生误报。进程最后均正常返回 0。

### 4.3 可见性与遍历顺序

顶层定义按源码顺序处理。变量、结构体和函数从登记完成的位置开始可见；没有声明的情况下，对尚未出现的函数调用按“未定义函数”报告错误 2。处理函数定义时，先登记函数签名，再分析函数体，因此允许函数递归调用。

## 5. 数据模型

### 5.1 类型

类型结点采用下列逻辑分类：

```text
TYPE_ERROR     错误占位类型，用于抑制级联诊断
TYPE_BASIC     int 或 float
TYPE_ARRAY     元素类型和当前维长度
TYPE_STRUCT    结构体字段序列及内部身份
TYPE_FUNCTION  返回类型和有序形参类型序列
```

数组声明从内到外形成嵌套类型。等价比较忽略每一维的具体长度，但保留维数和元素类型，因而 `int[5]` 与 `int[10]` 等价，`int[5][10]` 与 `int[50]` 不等价。

结构体字段使用有序链表，每项保存字段名、字段类型和声明行号。函数签名保存返回类型和有序形参列表。

### 5.2 符号表

采用带链地址法的哈希表，符号类别包括：

- 普通变量或形参；
- 函数；
- 结构体标签。

普通变量与结构体标签之间按照实验要求检查命名冲突；函数单独按函数规则检查。结构体字段保存在其结构体类型内部，不作为普通变量插入全局表，同一结构体内的重名字段报告错误 15。

所有语义对象在一次编译期间持续有效，由集中分配链记录并在分析结束时统一释放，避免 AST 中保存的类型指针失效。

## 6. 语义遍历与接口

公开入口设计为：

```c
void semantic_analyze(Node *root);
```

内部遍历按语法非终结符划分：

- `ExtDefList/ExtDef`：登记全局变量、结构体和函数，随后分析函数体。
- `Specifier/StructSpecifier`：构造基本类型或结构体类型。
- `VarDec`：把标识符及数组维度包装成完整类型。
- `DefList/Def/DecList/Dec`：处理变量或结构体字段定义及初始化。
- `StmtList/Stmt`：检查复合语句、表达式语句、返回、条件和循环。
- `Exp`：返回表达式类型、是否为合法左值以及是否已经发生根本错误。
- `Args`：收集实参类型并与函数签名逐项比较。

表达式结果包含 `type`、`is_lvalue` 和 `poisoned` 三项。未定义标识符等根本错误返回 `TYPE_ERROR/poisoned`；其父表达式只继续必要遍历，不再报告由该错误直接派生的类型不匹配。

## 7. 类型等价规则

### 7.1 通用规则

- 基本类型：只有同为 `int` 或同为 `float` 才等价。
- 数组：维数相同且最终元素类型等价；每维长度不参与比较。
- 函数调用：实参与形参个数相同，且每个位置的类型等价。
- `TYPE_ERROR`：只用于继续分析，不视为真实的可赋值类型。

### 7.2 选做 2.3：结构等价

结构体名称和字段名称均不参与等价判断。两个结构体等价，当且仅当：

1. 字段数量相同；
2. 按声明顺序对应的字段类型递归等价。

例如，`struct A { int x; float y; }` 与 `struct B { int p; float q; }` 等价；若字段顺序、数量、数组维数或基本类型不同，则不等价。匿名结构体也使用相同规则。比较函数记录正在比较的类型对，防止异常输入造成递归死循环。

此规则只改变类型等价判断，不改变结构体字段选择：`a.x` 仍必须在变量 `a` 自身的结构体定义中查找字段 `x`。

## 8. 错误 1—17 的检测位置

| 类型 | 含义 | 主要检测位置 |
|---:|---|---|
| 1 | 变量未定义 | 标识符表达式查普通变量表失败 |
| 2 | 函数未定义 | 函数调用查函数表失败 |
| 3 | 变量重复定义或与先前结构体同名 | 登记全局变量、局部定义或形参时 |
| 4 | 函数重复定义 | 登记函数定义时 |
| 5 | 赋值号两侧类型不匹配 | 赋值表达式类型比较 |
| 6 | 赋值号左侧不是左值 | 赋值表达式的 `is_lvalue` 检查 |
| 7 | 操作数类型不匹配或不适用于操作符 | 算术、关系、逻辑、负号和非运算 |
| 8 | `return` 类型与函数返回类型不匹配 | 分析返回语句时 |
| 9 | 函数实参与形参不匹配 | 调用表达式的参数列表检查 |
| 10 | 对非数组使用下标 | 下标表达式检查基表达式类型 |
| 11 | 对普通变量使用函数调用 | 调用表达式命中变量而非函数 |
| 12 | 数组下标不是整数 | 下标表达式检查索引类型 |
| 13 | 对非结构体使用点运算 | 字段访问检查基表达式类型 |
| 14 | 访问不存在的结构体字段 | 在当前结构体字段链中查找失败 |
| 15 | 结构体字段重名或字段定义时初始化 | 构造结构体字段列表时 |
| 16 | 结构体标签与先前结构体或变量重名 | 登记具名结构体时 |
| 17 | 使用未定义结构体定义变量 | 解析 `struct Tag` 引用时 |

诊断统一为：

```text
Error type [n] at Line [line]: [message].
```

其中 `[message]` 使用简洁稳定的英文描述。错误写入 `stdout`。同一源码行因同一根因产生多个候选错误时，只保留最基础、最先发现的错误；不同根因和不同行继续检查并报告。

运算规则严格遵守实验约束：算术运算只接受相同的 `int` 或相同的 `float`；逻辑、`if` 和 `while` 条件只接受 `int`；关系运算要求两个操作数为相同基本类型并产生 `int`。

## 11. 风险与控制

- **AST 形态不一致**：先为实验一所有产生式建立结点形态表，再按实际子结点位置访问，避免凭字符串猜测。
- **错误级联**：使用 `TYPE_ERROR` 和 `poisoned` 标记，仅抑制直接派生错误，不跳过兄弟子树。
- **选做越界**：为 2.1、2.2 建立反向测试，并在报告中明确“仅实现 2.3”。
- **结构等价遗漏递归情形**：所有类型比较统一经过一个递归函数，不在赋值、返回、传参处各写一套规则。
- **编译环境差异**：禁止第三方 C 库，使用 C89/C99 范围内的普通标准库接口，并以助教版本为最终标准。
- **压缩包层级错误**：从独立暂存目录生成 ZIP，随后用 `unzip -l` 验证顶层直接出现 `Code/` 和 `report.pdf`。
