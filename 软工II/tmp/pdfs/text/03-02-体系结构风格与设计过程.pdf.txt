体系结构⻛格的概念
体系结构⻛格（Architectural Style）是⼀组设计决策的集合，它规定了：
⼀组组件类型（如过滤器、层、服务）
组件之间的连接⽅式（如管道、调⽤、事件）
组件交互的约束规则（如分层只能调⽤相邻层）
⻛格 = 组件词汇 + 连接器词汇 + 拓扑约束
为什么需要⻛格？
提供经验复⽤ — 前⼈验证过的设计⽅案
提供通⽤词汇 — 团队沟通的共同语⾔
明确质量属性权衡 — 每种⻛格有特定的优劣

⻛格 vs 模式 —— 区别 [SW EBO K 2.2]
 
维度 体系结构⻛格 (Style) 设计模式 (Pattern)
作⽤范围 系统全局组织⽅式 局部重复问题的解决⽅案

案例对⽐：KW IC 实验
问题描述 [Parnas 1972]
KW IC（Key W ord in Context，上下⽂关键词索引）系统：
输⼊：⼀组有序的⾏，每⾏是有序的词序列
处理：对每⾏进⾏循环位移（将⾸词移到末尾），⽣成所有位移变体
输出：按字⺟顺序排列的所有循环位移结果
示例：输⼊ "Software Architecture"
→ 输出 "Architecture Software", "Software Architecture"
实验⽬的
⽤ 5 种体系结构⻛格实现同⼀问题，对⽐各⻛格在可修改性、可复⽤性、性能上的差异。

KW IC：五种体系结构⻛格实现对⽐
⻛格 控制⽅式 数据共享 耦合程度 核⼼特征
MS1 主程序-⼦程序 主程序顺序调⽤共享存储 + 索引 紧耦合 空间⾼效，数据⽆隐藏
MS2 主程序-⼦程序 主程序顺序调⽤共享存储 + 完整字符串紧耦合 直观易懂，空间开销⼤
O O  ⾯向对象 对象协作 接⼝访问，内部隐藏松耦合 信息隐藏，易于变更数据表示

同⼀需求，⻛格选择决定了系统的演化能⼒

--- PAGE 14 ---
KW IC 实验：变更场景分析
三种典型变更
变更类型 要求 各⻛格适应性
数据表示变更⽤完整字符串代替索引存储MS1 需改所有模块；OO  仅改内部实现
算法变更 按需⽣成位移（⽽⾮全部⽣成）PF 需改过滤器链；ES 可调整事件响应策略
功能扩展 过滤噪声词（如 "a", "the"） MS 直接修改共享数据；PF 新增过滤器即可
实验结论
M S：适合空间敏感、变更少的场景
O O ：适合数据表示可能独⽴演化的场景
PF：适合数据流式、增量处理场景，但难以交互
ES：适合功能动态扩展场景，但控制流复杂
核⼼启示：没有最好的⻛格，只有最适合需求的⻛格

分层体系结构原理
严格分层 (Strict L ayering)
每层只能调⽤直接下层
层间依赖关系清晰
修改影响范围可控
例：OSI 七层⽹络模型

允许跨层调⽤
提⾼运⾏效率
降低开发复杂度
例：⼤多数企业应⽤

三层架构详解
核⼼原则：上层依赖下层，下层不依赖上层；每层通过接⼝暴露服务。

三层架构 — 各层职责

业务逻辑层Business Logic 实现业务规则、协调⼯作流 Spring Service, EJB

分层⻛格的四⼤优势
优势 说明 示例
封装性 每层内部实现对外隐藏 切换 MySQL 到 PostgreSQL 不影响业务层

性能开销 — 层间调⽤带来额外开销

public class BookController {

// === Controller 层  ===
@Controller
public class BookController {
    @Autowired private BookService bookService;
    @GetMapping("/books")
    public String listBooks(Model model) {
        List<Book> books = bookService.findAll();
        model.addAttribute("books", books);   // 传递数据给  View
        return "bookList";                     // 选择  View 模板
    }
    @PostMapping("/books")
    public String addBook(@RequestBody Book book) {
        bookService.save(book);                // 更新  Model
        return "redirect:/books";              // 重定向刷新
    }
}
// === Service 层（ Model 的⼀部分） ===
@Service
public class BookService {
    @Autowired private BookDao bookDao;
    public List<Book> findAll() { return bookDao.selectAll(); }
    public void save(Book book) { bookDao.insert(book); }
}
